## 根拠と方法

C2-003 holdoutの60 runは全て80 Actionを使い切っていた。公開starter `agents/agent.py` の既定`MAX_ACTIONS=80`はループ回避上限であり、候補agentの`MAX_ACTIONS=79`はstarterの`action_counter <= MAX_ACTIONS`と合わせて1ゲームあたり80要求を許可する。action上限だけを変え、係数・Action選択・RESET・座標方針は固定した。評価器は公開環境5件×3 seedを各上限で実行し、baseline出力と公開開始状態の一致を確認した。

starter source SHA-256: `85655f7a11a105e50bba76efd00bebf8056d02ddbae827a8f8a5b46e849fc087`。

## 結論と次工程

dev acceptanceを満たさないためholdout、`MyAgent.main()`長時間運転、candidate Notebook再生成、Kaggle kernel更新は行わない。ローカルdevでAction上限を増やしてもlevel完了が増えず、no-op/GAME_OVER/記録サイズだけが増えるため80を維持する。これは公開5環境での結論であり、hidden競技performanceの判断ではない。

候補v4とofficial scoreの差は未測定のまま。次のC1候補は、公式`FrameData.frame`の複数gridを現在境界層が最後のgridだけに縮約するかを測り、アニメーション途中の公開情報が失われているかを公開環境だけで診断する。
