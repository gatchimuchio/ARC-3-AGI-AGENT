# ARC3-RUN-002 C4-004 事前記憶runtime適用境界監査

- 実施日: 2026-10-23 JST
- 対象指示: [C4-004指示書](../../運用/ARC3-RUN-002/C4-004_事前記憶runtime適用境界監査.md)
- 判定: **事前記憶v0.4はHDS native状態ファイルではなく、ID別索引・既知解trajectoryを含む複合分析正本。runtimeへ正本全体を読み込まない。提出agentは空HDSを生成し、HDS学習更新を呼び出していない。汎用蒸留文は抽出素材であり、機械実行規則とは未確認。**

## 仕様・データ境界

ARC3 v2.0とAGENTS.mdはHDS v0.4.2および事前記憶v0.4を保持対象に指定し、事前記憶の利用と学習状態更新を開発優先項目に挙げる。同時に、ゲーム/level IDによる答え参照と成功trajectory再生を禁止している。事前記憶README/manifestは公式25ゲーム・183 level・5,112初期一手作用観測・再現検証済み9 trajectoryを記録する。

統合正本には25ゲーム別の機構・作用統計、9件のID/levelに結び付いた成功trajectory、7件の横断蒸留原則が同居する。183-level索引もレベル別構造を持つ。既知解trajectoryおよびID別統計はruntimeへ読み込んだり答え選択に使ったりしない。7原則はID-freeの文章だが、自然言語の設計原則であり、HDSの条件・結果へ対応する実行可能規則としてのschemaや適用gateは含まない。個別trajectoryを除くだけで安全なHDS状態になるとは確認できなかった。

## HDS形式と提出agent

HDS v0.4.2のnative loaderは形式版1〜3、最小支持数、最大条件数、識別子状態、台帳、状態履歴、原理履歴を要求する。事前記憶の統合正本は独自schema arc3-hds-prior-memory-canonical-v0.4で、native HDS state keysを持たない。read-only in-memory loader検査はValueErrorで拒否した。

提出agentは各MyAgent instanceで新しい空HDSを生成し、開始観測の候補をread-only照会する。action後は探索方針の応答記録を更新するが、HDSの処理する()は呼ばない。C1-002のHDS shadow学習は別の評価専用経路であり、後半100予測は多数派基準と同じ100/100で、runtime学習や性能優位を示していない。

## 採否と次工程

事前記憶v0.4、HDS v0.4.2、提出agent、candidate v4、Notebook/kernel、AGENTS/current stateは全て不変更。現在の証拠だけでは事前記憶を提出runtimeへ安全に適用可能なHDS stateへ変換できないため、直接importは保留する。汎用原則を実装する場合は、ID-freeな条件・結果への明示的変換と、独立公開ゲームでの転移比較を別taskで証明する。

次単位はC1-006として、公開multi-frame応答のID-free特徴を使うshadow予測が既存のAction別多数派基準を超えるか、dev環境だけで検査する。HDS・提出runtimeへの接続はしない。
