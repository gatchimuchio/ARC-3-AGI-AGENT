- Kaggle public scoreはbaseline v5 `0.00`（submission `57527856`）からcandidate v4 `0.25`（submission `57541830`）へ`+0.25`。どちらも同じcompetitionの`COMPLETE`結果で、公開指標として比較できる。
- candidate v4はNotebook version 4、bundle SHA-256 `974029af7f66b774c96af3cf86b2344905bf68a0c83445fd366c74dd779e54d9`。S2公式記録でNotebook・manifest hashとsubmission IDを固定した。
- Kaggle submission historyのprivateScoreは空欄。submission `57541830`のepisodes照会も`No episodes found`。ゲーム別/レベル別到達、Action数、HOLD、失敗signature、実行時間は公式応答から取得できず、score増加の内部因果は未特定。
- 公開score差分は候補全体の比較。C2-003 no-op罰、C3-001 RESET再試行、C3-002座標fallbackなど個別変更の因果効果へ分解しない。

## ローカル候補の到達状況

C6-001の公開holdout 20環境×Action seed 7/31/73、各最大80要求では、60 run合計4,800 Action、完了levels 5、WIN 0、no-op 415、GAME_OVER/RESET 29/29。candidate bundle内policyとworkspace defaultのAction-response列は60/60で一致した。この値は公開環境での局所観測であり、Kaggle hidden評価の内訳へ換算しない。

従前の個別診断では、Action6連結成分内の再選択は703回中5回で低頻度、GAME_OVER後に同盤座標cacheが有効な割合は0.0244%で小さかった。color統計resetはholdoutでno-opを415→444へ増やし、単純な中間Frame no-op罰免除は開発5環境で35→34に留まり、採用されていない。これらの結果から、直近の大きな改善候補として同じ再選択/cache/no-op代理指標を再調整する根拠は弱い。

## 次に優先する観測

runtime agentは`観測駆動探索方針()`を乱数seedなしで構築し、内部で`random.Random(None)`を使う。公開holdout evaluatorはseed 7/31/73を明示しているため、公式score `0.25`の一回値を再現可能な内部試験へ直接対応づける証拠は不足している。

次単位C6-002で、policy/sourceを変えず固定holdout上のAction seedを増やし、level到達・WIN・Action数・no-op・GAME_OVERのseed間変動を測る。これは能力改善の主張ではなく、次の性能変更を採択する前に必要な再現性診断である。seed変動が小さい場合は、原因を未特定の公式score内部ではなく、公開holdout上のAction因果へ絞って次課題を選ぶ。変動が大きい場合のみ、Action seedの制御・頑健性を別指示書で検討する。

## 採否

candidate v4の公開score `0.25`を現行official previousとして採用・保存する。candidate runtime、HDS、Notebook/kernel、保護対象は変更しない。次の作業はC6-002乱数seed安定性診断とし、別指示書 [`C6-002`](../../運用/ARC3-RUN-002/C6-002_candidatev4乱数seed安定性診断.md) に限定する。
