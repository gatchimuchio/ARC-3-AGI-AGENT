# ARC3-RUN-002 C1-001 事前知識移植判定

## 判定

**提出seedとして不採用。** 実装状態は変えず、C1の失敗・棄却記録を残す。これは「HDS知識は一切転移しない」という一般結論ではなく、今回監査した保存状態から、提出agentへ安全に移植できる根拠付き規則seedが成立しなかったという限定判定。

## 入力境界

- `機構作用既知解_HDS正本.json` は12,499 bytes。`横断蒸留`の7項目は自然言語の運用定石で、HDSへ直接初期化できるpredicate・condition・action-effect規則ではない。
- 同ファイルのゲーム別 `作用実測`、`既知解.records`（9件）、trajectory、183レベル索引は答え表・ID引きの危険があり、提出seedの抽出対象から除外した。
- 利用可能な保存HDSは配色3,254,145 bytesと鏡像796,244 bytes。対応する公開原票は各々一つの異なるゲーム由来である。別ゲームholdoutは作れるが、各HDSが複数ゲームから学んだ横断規則であることはこの資料では確認できない。
- 配色・鏡像の専用接続は現行提出agentの静的import閉包に含まれない。現行agentが呼ぶ共通経路は列展開・複合配色・根付き順序鎖・形状目標対応の4語彙。

## 実測

再現コマンド:

```powershell
.venv\Scripts\python.exe 検証\ARC3事前記憶転移監査.py
```

追加で専用接続を確認した。配色保存HDSを配色初期観測へ与えた `配色候補を作る` は候補0。鏡像保存HDSを鏡像初期観測へ与えた `鏡像候補を作る` は候補7を返したが、APIの `実行許可` はfalseのまま。別ゲームの配色初期観測に鏡像保存HDSを与えるholdoutではHOLD候補6が返り、実行許可falseだった。候補数を転移成功へ数えず、action labelとの一致や反例保持を満たす採用根拠はない。専用接続の再現コマンドは `検証/ARC3事前記憶専用接続監査.py`。

## previous / current / delta と採否理由

- previous: 提出agentの空HDS＋共通4語彙で、候補0、HOLD。
- current: 既存保存HDSを同じ共通経路へ差し替えても、配色・鏡像の各公開初期観測で候補0。
- delta: 根拠付き実行候補0のまま。横断rule seedなし。公式scoreは引き続き初回 `0.00` で、このC1はローカル事前知識評価のみ。
- 反例側の警告: 異なるゲームの画像に鏡像保存HDSが候補を出すが、全件HOLD。これをpermissionへ昇格すると誤作用のおそれがある。
- 採否: どの保存状態も提出bundleへ加えない。保存HDSや専用connectorをゲームIDで選ぶ回避策も採らない。

## 次工程

C2では、HDS確定候補と分離した「観測駆動の探索Action」だけを扱う。候補がHOLDでも実験的に試す場合は探索出所として明記し、現観測で合法なActionのみを選び、各step後に再観測する。公開データでのaction label一致・進捗差・反例を評価するまでは提出へ接続しない。
