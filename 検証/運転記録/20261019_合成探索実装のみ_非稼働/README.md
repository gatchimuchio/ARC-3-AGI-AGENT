# 合成探索部品の実装保存（非稼働）

## 目的
既に独立レビューされた純粋な合成探索部品を、元の実装と同一のバイトで読み出せる形に保存する。今回の追加はこの説明、planner.py、自作合成検証の3ファイルだけとする。実行経路への接続や戦略の選択は行わない。

## 観測
元の部品は原子分割、後向き義務、全辺を残す有限探索、完全な証明経路、正の操作費用、資源上限時の保留を実装している。所属判定、作用、準備は呼出側から渡す関数であり、このファイルに学習済み規則や観測値は埋め込まれていない。
既存の統合検証は非同梱の学習台帳と保存観測を読むため、その検証ファイルを同梱すると単独実行できるとの誤解を招く。

## 原因
実装そのものの保存と、実行状態・応答・軌跡の原記録の保存は異なる範囲である。今回は実装と自作の小さな記号例だけを取り出し、元の統合実験への依存を明記する。

## 変更
- planner.pyは元の実装と無変更。同名の独立レビュー時の複製とも全バイト一致。
- test_合成探索.pyは今回新規作成。1〜2セル相当の自作記号例を中心に検証し、ゲーム画面、保存応答、native台帳、実軌跡を読み込まない。
- 元の英語名・辞書キーは保存対象の実装同一性のために保持する。新しい内部規範や学習機械の正本として採用するものではない。説明・検証の意味名は日本語とする。

## previous
開始mainは c3727bc903f6777e3637fdd0bd0eaf9830aa91bb。この実装の同一Git blobはそのmainのファイル一覧にない。元の独立レビューでは統合された条件付き探索として確認されていたが、今回の自立した合成検証は存在しなかった。

## current
実装の保存コピーと、Python標準ライブラリだけを使う8件の合成検証を用意した。ローカル検証は2026-10-19 UTCに全件成功。新規検証一式も別のコピー上で独立に再実行され、8件すべて成功した。公開内容の最終確認は別途必要であり、これだけで実行経路への採用を認めない。

## delta
読み出し可能な実装1ファイルと、原観測を必要としない方法単位の検証が追加される。学習内容、agentの能力、速度、成功レベル数の増加を示す変更ではない。

## regression
新規検証は以下を確認する。
1. 元実装のSHA256と、標準ライブラリ以外の読込・識別子分岐・ファイル操作の不存在の静的確認
2. 観測値・目標・作用範囲を区別する原子分割と、不正な所属判定の拒否
3. 後向き義務の矛盾・自己ループ・中断位置の保持
4. 全辺保持、独立した反復緩和との費用一致、最適な先頭辺と完全な証明経路
5. 部分修復と全面上書きの反例
6. 作用側から返る保留の保持
7. 状態数・辺数上限での全体保留と、途中の証明の不使用
8. 既達成・操作なしでも実行権限を追加しないこと

検証方法: このディレクトリで python -B test_合成探索.py
ローカル実行時はAS128 MiB、CPU10秒の上限を外側から適用した。所要時間は性能比較に使用しない。旧統合回帰やゲーム環境を再実行した結果ではない。

## limitations
- 単独のゲーム実行器ではない。実用上は観測の解析、適用範囲を満たす学習規則、照会結果の検証、所有者・受理・記憶の接続が別途必要である。これらの依存は今回同梱しない。
- 成功した探索は、渡された作用・準備・所属判定と正の費用が妥当であるという条件に依存する。任意の未検証入力に対する一般的な安全境界を保証しない。
- 全辺保存には有限の上限がある。上限で停止した途中結果を成功と扱わない。 支持する各先頭辺に対して保存する証明経路は1本であり、全経路を列挙したという主張ではない。
- 固定の探索・分割アルゴリズムであり、学習によって獲得した方策そのものではない。
- 原native状態、全応答、画像、軌跡、原証拠アーカイブ、HDS原典、非公開監査本文、opaqueゲーム・SDK・フォントは含めない。別の形式に埋め込んでもいない。
- HDS中核、AGENTS.md、権限文書、現在状態、既存の実行入口を変更しない。既存の失敗記録は元の保存先に保持されており、この3ファイルを全履歴の再現用一式とは呼ばない。
