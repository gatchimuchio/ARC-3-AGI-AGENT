# ARC3-RUN-002 C4-001 同一ゲーム内レベル間転移評価

## 判定

**持ち越し方針を変更しない。** 開発・holdoutともcompleted levelsと完了Action位置は変わらなかった。holdoutではcarryのno-opが少なかった一方、GAME_OVERが1件多く、公式目的に対する優位は確認できない。reset variantはruntimeへ採用しない。

## 実装と対象

- 正本: ARC3 v2.0／`ARC3-RUN-002`。C4「記憶→推論→適応」の局所評価。
- Official starter の `agents/swarm.py` は対象gameごとにAgentを生成して個別threadで実行する。候補 `MyAgent.__init__` は各instanceにHDSと探索方針を新規生成するため、ゲーム間で学習状態を共有していない。該当するローカルstarterのSHA-256: `swarm.py` `d9dc48f710f1b90a6552db0921293c7e89c8a925ed00a3faefa07ae19998ad39`、`agent.py` `85655f7a11a105e50bba76efd00bebf8056d02ddbae827a8f8a5b46e849fc087`。
- 現行探索方針の統計は同一Agent内でレベルをまたいで累積する。前C2-003でseed73の第二levelが15→5 Actionになったが、no-op罰変更と同時だったため持ち越しの効果は未分離だった。
- 評価器に任意の `--ablate-level-transfer` を追加。レベル完了時に方針統計だけを初期化し、乱数生成器状態を保持する。runtime agent、HDS、Notebook bundleは変更していない。評価器SHA-256 `7bd0139901f218b5920d36a770a4d17e87906742fd8c0fe683cad0e94aab16a5`。
- 25公開環境の既存分割（split seed `20261022`）を維持。開発5環境をseed 7/31/73、holdout20環境をseed31で各最大80 Action、GAME_OVER後のSDK RESET有効として比較した。
