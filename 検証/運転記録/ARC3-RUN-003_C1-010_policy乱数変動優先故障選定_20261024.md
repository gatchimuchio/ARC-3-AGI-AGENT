# ARC3-RUN-003 C1-010：public policy乱数変動の優先故障選定

## 選定

次の限定課題は、観測駆動探索policyで**同じ公開初期条件から到達level数がpolicy乱数seedにより変わる**再現性欠陥とする。

これは公式score `0.25`の原因だとは特定できない。Kaggleの公開結果はaggregate scoreだけで、game/level別episodeが未取得のため公式内訳との直接照合はできない。C1-010の選定は、残存する公開候補の中で複数回のlevel到達差が観測され、seed処理の単一要因ablationを限定実行できる点に基づく。

## 根拠と他候補の扱い

- C0-003/C6-003では公開holdout20環境のpolicy seed 10条件で到達levels 1〜4、WIN 0を観測。同一環境seed31・初期公開条件20/20を揃えた範囲で、現行乱数源がAction列・到達levelの変動へ影響している。最良seedだけを選ぶとholdout tuningとなるため使わない。
- C2-022では初期公開board・legal Action集合から一度だけhash seedを作るvariantが開発5環境×environment seeds 7/31/73でbaseline 1 level/seedから0へ低下し、同じ公開初期状態に一つの固定乱数列を当てる案を棄却した。
- C2-036は394回のHDS経験更新後も同じ394観測すべてでAction候補差0。Frame/盤面予測枝C1-006/008/009、Action集合文脈C2-020も採用根拠なし。no-op係数・Action報酬反映・初期hashseedを再調整しない。
- model-guided C2-027では公開25環境でlevel進行はあったがWIN 0、C2-034/035はreadiness前失敗。このmodel-memory branchを再開せず、現行公開探索policyの一要因だけを測る。

## 判断

C2-037は、単一初期hash seedの再利用ではなく、毎回の現在公開観測と現在のpolicy統計から決定的なtie-break RNG seedを作る評価専用ablationを行う。Action選択・報酬・UCB係数・記憶・legal gateを変えない。開発5環境×environment seeds 7/31/73でprevious/current/deltaを測る。どのseedでも完了levelsが減らない条件を満たさなければ棄却し、runtimeへ採用しない。

この検査は公開開発データの再現性・到達指標に限る。勝利、hidden performance、公式score改善を主張しない。

## 2026-10-24 JST：C2-037結果反映

- 現在観測ごとの決定seedは、開発5環境×environment seeds 7/31/73で各seedのlevels `1 -> 1`、WIN `0 -> 0`。GAME_OVERが全seed `6 -> 7`となったため、事前実装gateで棄却した。no-op差はseedごとに混在。
- 既存holdoutでのpolicy seed変動は引き続き観測事実だが、今回の開発条件ではlevel改善として再現しなかった。初期hash seed・毎選択hash seedの同系統を再調整せず、C1で別の因果候補が公開証拠から支持されるまで性能改変を追加しない。
