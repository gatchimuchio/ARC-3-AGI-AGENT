# ARC3-RUN-002 C1-007 複数Frameの境界保持read-only監査

- 実施日: 2026-10-23 JST
- 指示: [C1-007指示書](../../運用/ARC3-RUN-002/C1-007_Frame列境界保持read-only監査.md)
- 判定: **SDK Frame列は境界で保持される。探索Actionの選択・報酬とHDS候補照会は最新盤面だけを見るため、途中Frameは境界で消失するのではなく現行候補の判断入力に使われていない。**

## 観測経路

ARC3境界の盤面変換はSDKのframe配列の各gridを盤面列へ複製する。HDS観測payload builderも全盤面フレーム列を出力し、境界unit testは2枚のgridがそのpayloadまで保持されることを確認する。実SDK公開環境のC1-003測定では、25環境・2,000応答に7,833 gridが含まれ、654応答（32.7%）が複数gridだった。

一方、現行提出agentの探索Action経路はAction選択と応答報酬で作用前後の最新盤面だけを参照する。共通HDS候補照会も最新盤面1枚を構造語彙へ渡す。HDS観測payload builderの呼出しは提出agentのruntime経路では見つからず、現行agentは初回診断用の候補照会後も探索Actionを継続する。相別Frame記録関数は他の分析・語彙モジュールから呼ばれているが、提出agentの選択/報酬経路では呼ばれていない。

したがって、SDKや境界が複数gridを最後の1枚へ潰すという情報損失仮説は棄却する。現行runtimeの選択・報酬が最新盤面だけを使うことは確認したが、中間Frameを組み込む効果はC1-005で受入条件不成立、C1-006でも多数派を超えず、追加のruntime接続根拠はない。
