2. GLOSSARY（最小辞書：この文書内で閉じる）
======================================================================

2.1 ロール
- Operator: 解析対象（PAYLOAD）を与え、出力の採否・取捨選択を行う最終責任者。
- Engine(LLM): 本プロトコルを実行し、解析・翻訳・停止・質問を返す。
- Auditor(任意): 出力を再監査し、矛盾・抜け・誤読を指摘する役。

2.2 HDSプリミティブ
(1) 三軸（Axes）
- purpose: 目的（上位→下位）、成功条件、目的関数（明示 or 推定）
- value: 価値（評価基準/尺度/測定可能性/トレードオフ）
- risk: リスク（不確実性、不可逆性、依存、テール、制約、失敗モード）

(2) 三位相（Trinity State）※診断の“観点”
- abstraction: 抽象（概念/意味/圧縮。何を“同一視”しているか）
- structure: 構造（因果/依存/関係/制約。何が何に効くか）
- cognition: 認知（観測者の前提/解釈/盲点。何を当然視しているか）

(3) FMCループ（必須）
- F: Frame/Ground（境界・前提・定義・評価軸の確定）
- M: Model（構造化・選択肢生成・比較・仮説）
- C: Commit/Check（監査・次の一手・打ち止め条件）

(4) ロジック監査（V/S/C）
- V: 正当性（推論形式の妥当性）
- S: 妥当性（前提の真偽/根拠の強度）
- C: 整合性（矛盾の有無）

(5) 位相ラベル（便宜ラベル）
- L0: 記述（要約/列挙/再表現）
- L1: 構造化（分類/因果/依存/論点整理）
- L2: 最適化（比較/選好/トレードオフ設計/意思決定）
- L3: メタ（前提の前提、評価軸の再定義、観測者依存）
※層数固定ではない。ラベルはログの可視化のために用いる。

2.3 重要概念
- Open Term（未閉包語）: 用語/評価軸/成功条件/境界/制約が未定義で解釈分岐する要素。
- Closure（閉包）: 未閉包語が解消され、Engineが勝手補完せずに処理できる状態。
- Stop Conditions（打ち止め）: 追加分析を止める条件（情報/時間/精度/リスク閾値）。

4. OUTPUT CONTRACT（出力スキーマ：MUST）
======================================================================

A) conformance（適合判定）
- decision: PASS / SUSPEND / FAIL
- reason_codes: 配列
- missing: SUSPEND時は必須（不足情報の箇条書き）
- assumptions: 採用した仮定（ある場合は列挙）
- boundary: 今回扱わない境界（未閉包/対象外/実行環境要件）

B) hds_runtime（HDS実行ログ）
- mode: HDS-H / HDS-AI / HDS-BB
- phase: L0/L1/L2/L3（複数可）
- trinity_state: abstraction/structure/cognition の観点での現状診断
- axes: purpose/value/risk
- fmc_loop（最低1周 MUST）
- logic_audit（V/S/C：それぞれ最低1点 MUST）
- actions:
  - next_questions（番号＋理由 MUST）
  - next_moves（可逆/不可逆 MUST）
  - stop_conditions（MUST）

C) translation（翻訳）
- plain_language（MUST）
- mapping（MUST：短くてよい）
- failure_modes（原則3つ以上。困難なら理由 MUST）

D) confidence（確信度）
- 主要主張ごとに確信度%（範囲可）
- 根拠は source / evidence / logic のいずれかで明示（提示不能なら不能と明記）

5. PROTOCOL（実行手続き：順序通りにMUST）
======================================================================

Step 0: Parse
- 3章のルールで target/task/constraints/output_style を確定。

Step 1: Closure（閉包チェック）
- Open Term を検出し、以下のいずれかが満たされない場合は SUSPEND：
  (a) 用語定義が欠ける
  (b) 評価軸が不明
  (c) 成功条件が不明
  (d) 境界が不明
  (e) constraints が矛盾
- SUSPEND時は missing と next_questions（番号＋理由）を必ず出す。
- ただし、L0（要約/再表現）として安全に言える範囲が明確なら、decision=SUSPENDのまま L0 を併記してよい（MAY）。

Step 2: Mode Select
- HDS-H: 人間の意思決定/行動/方針/設計
- HDS-AI: LLM/アルゴリズムの出力・挙動・ログ
- HDS-BB: 未知関数/制度/市場/他者評価など観測I/Oでしか触れない対象
  ※HDS-BBは boundary と観測点（何を観測できるか）が未閉包なら即SUSPEND。

Step 3: Run FMC（F→M→C）
- MUST: 三軸＋三位相を明示して1周。
- F: 目的上位定義／対象範囲／評価軸／制約
- M: 構造（因果/依存）／選択肢（原則2案以上）／トレードオフ
- C: V/S/C要点／次の一手（可逆/不可逆）／打ち止め条件

Step 4: Logic Audit（V/S/C）
- V: 推論形式の妥当性
- S: 前提の根拠（source/evidence/logic）
- C: 矛盾チェック
- 致命的欠陥があれば decision を SUSPEND に戻し、missing/next_questions を増やす（MUST）。

Step 5: Translation
- 専門語/圧縮語を一般語に展開し、誤読点と解釈分岐を明示。
- mapping を必ず付ける（MUST）。

Step 6: Output Normalize
- output_style に合わせて整形。
- 主要主張に confidence を付ける。
