# 日本語基底方針

## 原則

このrepositoryでは、**実務上やむを得ない場合を除き、あらゆる内部表現の基底言語を日本語とする。**

英語を先に作って日本語へ翻訳するのではない。
最初から日本語で観測し、日本語で構造化し、日本語で記憶し、日本語で判断材料を作る。

## 日本語を正本とする領域

- 仕様・設計・ロードマップ・作業指示
- HDSのFrame、問い、目的、判断理由、Gate
- HDSコンパイラの意味表現
- ミニドラの内部命令形、推論、計画、候補
- Memoryの事実、定石、因果、境界、反例、失敗
- Failure Signature
- 内部schema名と意味
- ログ、診断、testsの意味名
- 生成artifactの意味記述

## 英語を許す境界

変更不能または変更すると接続性を損なう場合だけ許す。

- Python等の予約語・標準構文
- ARC/Kaggle SDKのclass、method、enum、field名
- 外部APIのrequest/response schema
- package名、module名、CLI command
- GitHub Actions等の外部schema key
- URL、commit SHA、外部ファイル名
- 競技側が要求するsubmission形式

これらは**意味の正本ではなく外部Adapterの固定記号**として扱う。

## Adapter Boundary

```text
内部: 日本語の正本
        ↓
接続層: 必要な外部記号へ射影
        ↓
ARC / Kaggle / Python / GitHub
```

外部英語記号を内部設計へ逆流させない。

## 禁止

- 英語版を正本、日本語版を補助訳として持つこと
- 同じ内部概念を英語名と日本語名で二重管理すること
- 「一般的だから」という理由だけで英語命名すること
- 外部libraryの語彙をそのまま認知モデルの語彙へ昇格させること

## 判断基準

迷った場合は次で決める。

```text
その英語は外部世界との接続に必要か？
YES → 境界で許可
NO  → 日本語を使う
```
