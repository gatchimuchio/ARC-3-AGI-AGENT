# リポジトリ運用モデル

このrepositoryは四つの面を混同しない。

## 1. 規範面

何を作るべきか、誰が決めるかを保持する。

- `AGENTS.md`
- `運用/`
- `設計/`

## 2. 現在状態面

現在何を選択しているかを保持する。

- `制御/現在状態.json`

現在の戦略は未選択である。

## 3. 実装面

今後の実装は責任主体ごとに分ける。

- `HDS/`
- `ミニドラ/`
- `記憶/`
- `接続/`

## 4. 証拠面

実際に何が成立したかを保持する。

- `検証/`
- runtime結果
- ARC3公式sample結果
- Kaggle結果

文書上の完成宣言で観測結果を上書きしない。

## 履歴の扱い

旧rev・旧実装・旧artifactは現行作業木から除去する。
Git履歴は保存するが、自動的な権威・依存・再利用元にはしない。

## 状態遷移

戦略、作業点、完成状態を変更する場合は、Ownerの目的と対応する明示的な遷移として行う。
cleanupやtest PASSを理由に暗黙遷移しない。
