## 6. 採点待ちとCodex中断の対策（v2.0の再発防止）

**「自動で継続せよ」は継続運転の実装ではない。** 次のいずれかを実際に成立させる。

- 実行セッション内で監視ループを継続できる場合：公式IDを再照会し、待機間隔・時限・状態をログ化。待機中に無関係な最適化を開始しない。
- セッションが終わる場合：`検証/運転記録/ARC3-RUN-003_運転台帳...`に**次回起動の入口と再開コマンド**を書き、次回最初に読み込んでその地点から再開。
- 既に許可された定期実行機構がある場合：次の採点照会または次回提出日を設定し、実際の動作を確認。新しい権限・資格情報登録が必要ならそこだけを承認照会。

同一提出IDをキーとして重複投稿を防ぐ。何も起動しない構成を「24時間自律運転成立」と報告してはならない。スケジューラ未成立のときは**未成立と明記**し、別の有効な再開経路を確保する。

## 7. 絶対禁止と失敗の是正

- 提出受付だけで「公式スコア取得」「初回提出工程完了」と書く。
- `PENDING`を無監視で放置したまま、性能改良の論拠なく別工程へ進む。

- 非動作agentがテストPASSしたことを攻略機能完成と取り違える。
- `AGENTS.md`／保護された現在状態ファイルの無断変更、改変履歴の消去、責任主体の自己承認。
- Kaggleの提出枠を無視した連打、個別ID別の答え表・replay lookup・隠し評価への依存。

一度のCLIエラーは作業停止条件ではない。ログを保存し、コマンド契約を検査し、修復して再試行する。改良案の失敗も次の原因追跡の入力とする。
