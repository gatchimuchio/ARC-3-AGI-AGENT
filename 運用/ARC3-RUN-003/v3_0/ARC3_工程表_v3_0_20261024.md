## 0. 運転方針

**第一のクリティカルパスは、既存提出の公式採点結果を得ること。** 初回のScore未取得で学習・性能最適化を開始しない。スコアを得たら初めて、行動可能agentの成立→公式能力基準線→横断学習→日次公式比較へ進む。

工程番号だけ進んでも受入条件を満たさなければPASSにしない。失敗・待機は工程内部の状態として管理し、次に取る操作と再開点を常に保持する。

## 7. 1タスク実行契約

各単位の開始時に、`AGENTS.md`／保護状態／本版／最新SHA／Kaggle履歴／対象コードを再観測してから、次の記録を作成する。

```text
指示ID / 工程ID / 初期SHA / Notebook版 / 提出ID / 公式状態 / 公式スコア
対象と問題 / 観測した原因 / 変えてよい範囲 / 保持条件
実装差分 / 試験条件 / previous / current / delta / 失敗署名
採否 / 次工程 / 次回照会時刻 / 再開方法 / 外部阻害と必要な権限
```

重要：`SCORE_READY`未成立の間は同じ提出IDを追い、状況を台帳へ**追記**する。監視待ちを「何もせず終了」にしない。次回起動を保証する機構が利用不能なら、その不成立も監査結果として明記する。
