# 公開5ゲーム: ACTION6の点選択だけをHDSに委ねるpaired screen

## 判定

**REJECT — 性能改善として採用しない。** DのAction種別をAの基線に固定し、HDSがACTION6の点だけを選び直す条件でも、ローカルSDK平均scoreは低下した。

## 実験条件

- 実施: 2026-10-29。全腕完了まで2,069.01秒。Dは2,030.70秒。
- main: `91dfe97ada67212d7778ecdc34ab4e6f28fef65b`。比較基準: `4f37b4bbeaafcca736a57c17b02d51febcad56da`。
- Python 3.12.10、arc-agi 0.9.8、arcengine 0.9.3。公式Starter commit `4743e7d0aaae0ded0d98a89a7e282e63564cd58b`。
- seed: split 20261022、environment 0、policy 31025。A/B/D各5件、各80 action。初期状態一致5/5、A/B行動trace一致5/5。
- 対象は過去使用済みの公開ゲーム5件で、holdoutではない。
- DではAction種別をAの選択に固定した。ACTION6の点だけ、公開盤面から作る一般特徴`click_area_log2`、`click_fill_percent`、`click_touches_border`、`click_anchor_role`を使ってHDSが再選択できる。

DではHDS経験更新397回、選択判断175回、点のみのoverride136回。DのAction traceは4/5でAから分岐し、違法Action、SDK action不一致、step/dispatch不一致、Agent/SDK warningはいずれも0だった。Action別件数はA/B/Dで完全一致。したがって今回のD介入はaction classではなくACTION6の点選択に限定された。

no-opは6回減ったが、SDK平均scoreは低下しlevel到達・勝利は増えなかった。前screenの「action class切替がscore悪化を生んだ」という仮説は支持されず、点選択介入も合格しなかった。可視変化予測を点選択の報酬として使う設計を採用しない。5件の観測だけで一般原因までは断定しない。

Dの合計処理時間は2,030.70秒（平均406.14秒/件）。全体時間は2,069.01秒。ローカル評価の時間であり、Kaggle 9時間実行の保証ではない。

## 学習効果・限界

DはAと同じAction種別を維持しながら、4/5でクリック点を変えた。一方、SDK scoreは0/1/4（改善/悪化/同点）で、点候補の一般化学習による性能改善は未実証、結果は棄却。ゲームごとにAgent/HDS状態を新規化しており、ゲーム間転移は測っていない。得点はローカルSDK scorecardで、Kaggle公式scoreではない。

## 次の仮説

`visible_change`は結果予測としては学べても、得点の代理報酬としては不十分。可視変化は探索情報価値として分離し、HDSがlevel進行などの直接的な公開目的信号を持たないときはACTION6の点を介入変更しない案を次に検証する。次runでは公開応答から得た進行・反証をどの条件で採用するかと、action/point別override、scoreを同時に記録する。
