# Starter異常伝播と学習経路の検査（2026-10-29）

## 提出経路

旧Starterでは、ゲーム一覧が空でも親処理が通常終了し、ゲームごとのthread例外をjoinした親が把握しない可能性がある。これはソース上の欠落で、実Kaggleで障害が発生したとの観測ではない。現mainの提出構築器はHOLD版で、旧実Agentをそのまま出力するものではない。

一時領域の試作は、元StarterのSHAが一致する時のみ限定変換し、空一覧、workerの例外・停止、環境の初期化、scorecard open/close、cleanup、ゼロ応答を検出する。失敗時も他ゲームを継続し、closeを一度試してから失敗を親に伝える。公開frameの保存を抑えるためrecordを無効化し、異常内容と識別子を標準出力しない。合成Agent・模擬transportの18検査はPASS。サーバーが操作を受理したかはクライアント側の応答数だけでは証明しない。

公開ゲーム1件のローカルFlask競技Gatewayと実Agentで、監視なし／ありの初期状態・行動列が一致し、各腕2 dispatch＝2 SDK wrapper応答＝2 server step、illegal 0、close 1、HDS Action認可falseだった。実施時、SDKのmodule-level GETの置換漏れでローカル擬似ホストへの接続が2回失敗し、transportを補ってから得た結果を採用した。Kaggleには接続していない。

この試作の**initial WINでのゼロ操作、実ゲームの複数並列、割込中のclose、Linux、Notebook結合、Kaggle Gateway、9時間完走は未検証**。試作は旧StarterのMITライセンス表示を保って公開可能な形に整え、これらの検査と資産の公開範囲確認を経るまではmainの提出経路へ採用しない。source-only試作・合成testと匿名結果はOneDrive作業領域にハッシュ照合して保全した。HDS本体、私的bundle、盤面、行動列は同梱していない。

## HDSの実際の接続

実Agentでは観測ごとにHDSを照会するが、公開5ゲームでの照会400回は候補作用ごとの有効な予測数ではない。優先選択0は、利用可能な順位候補が生成されなかったことを示す。Action 6は座標が未確定な段階では照会対象から除かれる。残りの候補について、適用条件・競合・予測の一意性など、どの条件が不採用の原因だったかは現在の記録だけでは未確定。更新394回も再利用可能な原理が成立した証明ではない。

さらに、現行経路はAgentごとにHDSを新規生成し、ゲーム境界でスコープを消去するため、この経路によるオンライン学習のゲーム間転移は未成立である。非公開の原理・観測・IDを出さずに照会の不採用理由を数える診断と、事前記憶／照会／更新を分けるA/B/C/D比較を準備中。照会自体が状態を変えるかも別途検証する。HDSのHOLDを確定作用へ読み替えない。
