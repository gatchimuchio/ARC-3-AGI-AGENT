# 競技Gateway境界と提出資源の確認（2026-10-29）

## ローカル競技APIの実測

固定SDK `arc-agi 0.9.8` / `arcengine 0.9.3` の `create_app` を競技modeで起動し、公開ゲーム1件を `Arcade(OFFLINE)` に接続した。通信にはFlaskのテストクライアントを使い、外部ネットワーク・Kaggle本番へは接続していない。`ONLY_RESET_LEVELS=true/false` の両条件で次を確認した。

- scorecardの初回openは200、2枚目は409、競技scorecardのGETは403。
- 初回RESETで環境を作成後、同じGUIDで直ちにRESETすると応答は200で、環境`step`呼出しは0回。ただしscorecardの操作数とreset数はそれぞれ1加算された。
- 公開された合法Actionを1回送ると`step`は1回。続く同じGUIDでのRESETも`step`は1回。GUIDを省略した同一ゲームの再作成は400。
- 初回のSDK wrapper生観測 `full_reset` は設定trueでfalse、設定falseでtrueだった。一方、APIが返す初回 `FrameData.full_reset` は両条件でfalseだった。

これらは**単一公開ゲーム・初回と1操作後のローカルSDK実測**であり、WIN後・複数レベル・実Kaggle Gatewayの挙動を証明しない。実Gatewayに同じSDK版と環境変数が適用されるかは未確認。観測経路が`full_reset`を差分比較の境界として使うため、値の差は調査対象だが、現時点で誤学習や公式スコア低下を断定できない。OFFLINE paired評価の操作数を競技APIの操作数へそのまま読み替えない。

追加で旧枝の実 `MyAgent.main()` を、実SDK `RemoteEnvironmentWrapper` と競技modeの `RestAPI` に接続し、通信層だけFlaskテストクライアントに置き換えて公開1ゲーム・8要求を実行した。dispatch／remote step／server stepはいずれも8、違法操作・server step不一致は0、観測対象としたSDK・Agent loggerの警告は0、HDS Action認可はfalse、scorecard GETは403だった。独立したscorecard loggerはプログラム上の警告集計に含まれないが、保存ログに警告表示はなかった。代表点候補はこの検査に含まず、レベル突破は0。実Kaggle Gateway、9時間完走、公式得点の証明ではない。先行する127.0.0.1のTCP接続試行は `ConnectionResetError`（WinError 10054）で失敗し、実Agentの検証前に通信なしのFlask transportへ切り替えた。
