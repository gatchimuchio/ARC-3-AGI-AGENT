## 競技提出ゲート

1. v5 source hashとC2-027の記録を一致させる。別の最新versionや作業ツリーNotebookを代用しない。
2. Kaggle Notebook metadataが対象competitionを参照し、Internet無効、GPU有効、コンペ用モデル・依存データが添付済みであることを確認する。
3. `KAGGLE_IS_COMPETITION_RERUN`時にlive Arcade gatewayから全公開環境一覧を取得し、offline pilot上限やplaceholder提出経路へ入らないことを確認する。
4. Kaggle公式要件のGPU実行9時間以下に対し、live設定が1 pass・最大532分/環境・RTX PRO 6000であることを確認する。モデルは公開Kaggle Model versionを使用し、そのカード記載licenseを記録する。
5. 公式提出履歴と提出枠を直前にread-only照会する。枠がない・source hash不一致・規約不適合なら提出せず、根拠を保存する。
6. 全ゲートが成立した場合のみ、既存version 5を指定して公式Competition Rerunを1回行う。kernel versionをpush/改変せず、受理ID・Notebook版・公式状態・public score・private scoreの有無・UTC時刻を追跡する。同じ版を重複送信しない。

## 保持条件と採否

公式履歴・候補version・既存提出を上書きしない。Competition Rerunの受付、Notebook COMPLETE、placeholder、local RHAEは公式採点完了の代用にしない。得点取得後は数値と提出IDを結び付け、B0/B1および既存提出との差を別工程で判断する。今回、AGENTS.md、`制御/現在状態.json`、HDS、shared runtime、candidate sourceは変更しない。
