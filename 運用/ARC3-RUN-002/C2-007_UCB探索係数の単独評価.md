# C2-007 指示書：UCB探索係数の単独評価

- 指示ID: `ARC3-RUN-002-C2-007`
- 版: 1.0／2026-10-23（JST）
- 対象: 観測駆動探索ActionのAction選択に使うUCB探索係数
- 前回基準: C2-003適用候補、`探索係数=0.8`、no-op罰`-1.0`
- 変更前方針SHA-256: `6e8134a3ebe63aefedfcde0b3062dd8a8e6497396d3083d875ad9a782f46b6d7`
- 変更前評価器SHA-256: `ae02e1df02a5c550a65500494e3e1d3c40e2ce2c24825ed2a6c90a38d2658d6e`

## 観測と仮説

C2-003版は同一公開holdoutで完了レベル5を維持し、no-opを460から415へ減らした。一方でWINはseed 7/31/73すべて0で、探索Actionは一度試したActionをUCB値で選び続ける。レベル進捗が報酬の主信号であるため、探索係数0.8が高すぎる場合、未完了のAction腕を試し続けて有効Actionの再利用を遅らせる可能性がある。

仮説: 初回に各合法Actionを一度ずつ試す挙動は維持し、その後のUCB探索係数だけを0.8から0.4へ下げると、開発環境で完了レベルを落とさず、不要Actionを減らせる。

## 目的

UCB探索係数一つだけの差が、公開Action応答に基づく進行・Action効率へ与える影響を分離評価する。HDS、報酬項、合法Action制御、座標選択、RESET、最大Action要求数は変更しない。

## 許可する範囲

- `検証/ARC3探索Actionローカル評価.py` に、探索係数を評価時に渡す引数を追加する。
- `検証/ARC3探索Actionローカル評価.py` と現行のC2-003基準出力のみを使った公開dev比較。
- devが受入条件を満たす場合だけ、開発対象外のholdout 20環境をseed 7/31/73で固定比較する。
- 結果記録の追加。方針の既定値は評価完了まで変更しない。

## 禁止と保持条件

- 可視変化係数、レベル進行報酬、no-op罰、報酬正規化、UCB式、ACTION6優先、座標選択を同時変更しない。
- game/level ID、filename、hash、hidden state、trajectoryをruntime選択へ使わない。
- HDS HOLD、WIN、SDK RESET、GAME_OVER再試行、Action要求80件上限、違法Action0、重複step0を維持する。
- HDS v0.4.2、`AGENTS.md`、`制御/現在状態.json`、正本ポインタ、v2.0文書、v1.0履歴を変更しない。
- Kaggle bundleまたはCompetition Rerunへ、dev結果だけで反映しない。

## 検証と事前受入条件

1. 同じ公開5件のdev split、environment/action seed 7/31/73、80要求上限、GAME_OVER RESETありで係数0.8と0.4を比較する。初期盤面一致を確認する。
2. dev候補は各seedの完了レベル合計が基準以上、illegal/duplicateが0、policy holdが基準を上回らないこと。no-op総数は3 seed合計で基準以下、かつ少なくとも2 seedで減ること。
3. いずれかを満たさない場合は候補を棄却し、係数を既定0.8のまま保つ。holdoutを実行しない。
4. devが全条件を満たす場合、方針を固定して20 holdoutを各seedで一度ずつ評価する。holdoutでは各seedの完了レベル合計を基準未満にせず、全seed合計no-opを減らし、illegal/duplicateを0に保った場合のみ候補採用を検討する。
5. 公式競技score・hidden環境性能をこのローカル評価から推定しない。採用時だけ次の候補bundle作成と公式枠確認へ進む。

## 終了条件

同一条件のprevious/current/delta、全seedの完了レベル・no-op・要求数・RESET/GAME_OVER・WIN・policy hold・illegal/duplicate、各出力SHA-256を記録する。受入不成立なら既定候補を維持し、失敗署名を次の診断へ渡す。
