# C2-001 指示書：HDS-HOLDと分離した観測駆動探索Action

- 指示ID: `ARC3-RUN-002-C2-001`
- 版: 1.0／2026-10-22（JST）
- 対象: ARC3提出agentの探索Action選択・応答更新
- 前回基準: Kaggle submission `57527856`、public score `0.00`。C1は移植可能seedを不採用。
- 前提記録: `ARC3-RUN-002_C0-初回基準線診断_20261022.md`、`ARC3-RUN-002_C1-事前知識移植判定_20261022.md`

## 目的と仮説

現行提出agentは初回の進行中観測後に終了する。C1で確認したHDS候補も実行許可がなく、これをActionへ昇格してはならない。目的はHDS判断とは別の**探索出所**を持つ適応的なAction方針を、公開観測だけで構成・評価すること。仮説は、各合法Action後に再観測し、観測された状態変化・進捗・失敗境界を使う探索なら、現在の0-action基線より有用な経験を取得できるというもの。

## 許可する範囲

- 薄い探索状態・選択ロジック・提出agent接続・targeted testsの追加。
- 選択入力は現在の公開frame、`available_actions`、同一agent run内で自分が送ったAction、直後の公開応答だけ。
- 各ActionはHDS確定Action／未確定候補／探索Actionのどれかを明示し、探索出所をHDS根拠と混同しない。
- 探索候補は現観測に結び付け、Action ID・座標・引数を現在のSDK契約で検査する。一つのstep後には次を選ぶ前に必ず再観測する。
- 公開教師記録のaction/responseは探索方針を反証するローカル評価に限る。ゲーム/level IDを学習・選択のruntime条件にしない。

## 禁止と保持条件

- ゲーム固有成功列、既知解・trajectory lookup、ID/filename/hash分岐、固定座標や固定Action列を使わない。
- `実行許可:false` をtrueに変更せず、HDS HOLD候補をHDS確定Actionとして送らない。
- 探索ActionをHDS学習規則の支持・採用へ自動昇格しない。作用前後の公開応答と出所だけを保存する。
- 現在の `available_actions` にないAction、不正座標、終了状態へのAction、同じ観測への二重stepを拒否する。
- `HDS/学習系統/v0.4.2`、保護対象、旧運転記録を変更しない。

## 検証

1. 公開action-response記録から複数ゲーム・複数状況の評価組を構成する。ゲーム単位holdoutを用い、使用データと未使用データを記録する。
2. 既存候補、観測駆動探索、単純ランダム探索を同じ公開情報・同じ合法Action集合で比較する。実行Action一致、公開進捗、失敗/終了、反復、HOLDを分けて測る。
3. 探索方針が答え列を再生せず、現在観測に応じて選択を更新し、未観測・矛盾・同値複数時に過剰な確定をしないことを反証する。
4. SDK adapterのmock/公式Starter offline testで、step一回、応答再観測、WIN/GAME_OVER停止、reset境界、作用許可との出所分離を確認する。
5. 学習指示の観測内容に評価正解が混入しないこと、Notebook bundleに解答/trajectory/識別子を梱包しないことを確認する。

## 終了条件

- 候補行動が合法で出所分離され、少なくとも2ゲームのholdoutでランダム基準より説明可能な優位があり、終了・反復・誤作用の保持条件を満たした場合のみPASS。
- 評価力不足、横断転移なし、または候補がHOLDしか返さない場合は不採用。候補件数だけを改善実績にしない。
- C2はローカル方針検証まで。合格してもKaggle再提出へは直結させず、別工程でNotebook再生成・同一条件評価を行う。
