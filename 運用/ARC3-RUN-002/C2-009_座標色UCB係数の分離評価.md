# C2-009 指示書：座標色UCB係数の分離評価

- 指示ID: `ARC3-RUN-002-C2-009`
- 版: 1.0／2026-10-23（JST）
- 対象: ACTION6座標選択の色別UCB探索係数
- 前回基準: C2-003 candidate、全UCB係数0.8、no-op罰-1.0
- 根拠: C2-007で全Action UCBを0.8→0.4にするとholdoutのACTION6 no-opは278→267へ減った一方、他Action no-op増で総no-opは415→425へ悪化。座標色UCBとAction-ID UCBは同じ係数を共有しており、座標色側だけを下げる効果は未分離。

## 仮説

Action-ID選択係数0.8を維持し、色別UCB係数だけ0.4へ下げると、低応答の色を追加探索する頻度が減り、Action-family selectionの変化を抑えながらno-opを減らせる。

## 許可する範囲

- `接続/観測駆動探索Action.py` に、Action UCB係数から独立した任意の色UCB係数を加える。既定は未指定なら従来通りAction UCB係数を使用。
- `検証/ARC3探索Actionローカル評価.py` に色UCB係数指定を渡し、出力へ保存する。
- `検証/test_観測駆動探索Action.py` に係数分離後の色選択と既定互換を確認する試験を加える。
- 同じ5件dev split、seed 7/31/73、80要求上限、GAME_OVER後RESETありで比較し、dev受入時だけ同じ開発対象外20 holdoutを各seed一度評価する。

## 保持条件

- Action-ID UCB係数は0.8固定。no-op罰、level報酬、new-board/visible-change報酬、初期Action順、ACTION6初手優先、盤面反復抑制を変更しない。
- ACTION6を合法集合から外さず、現盤面内の未試行座標・既存色別応答・座標範囲検査を保持する。
- 数値色IDを固定優先しない。各run内で現在盤面の可視色と作用応答からのみ色統計を更新する。
- game/level ID、filename、hash、hidden state、trajectoryを選択根拠に使わない。
- HDS HOLD、SDK RESET、WIN停止、80要求上限、違法Action0、duplicate step0を保持する。
- 既定係数とNotebook version 4は評価完了まで変更しない。HDS v0.4.2、AGENTS、現在状態、正本ポインタ、v2.0・v1.0文書を変更しない。

## 検証と事前受入条件

1. 係数0.8をprevious、Action-ID係数0.8＋色係数0.4をcandidateとする。初期盤面一致、選択の再現性、Action合法性を確認する。
2. devでは各seedの完了levelを基準未満にせず、合計no-opを減らし、少なくとも2 seedで減らすこと。policy holdは基準以下、illegal/duplicateは0。
3. dev不合格ならholdoutへ進まず、不採用として既定を維持。
4. dev合格時のみholdoutを実行する。各seedの完了levelを下回らず、総no-opを減らし、seedごとのno-opを増やさず、illegal/duplicate/holdを増やさない場合のみ採用を検討。
5. ローカル結果から公式scoreやhidden環境性能を推定しない。採用時だけcandidateを再構築し、Kaggle実行・提出枠確認へ進む。

## 終了条件

previous/current/delta、Action-family・色別クリック/no-op/level進行、要求数、RESET/GAME_OVER/WIN、HOLD、illegal/duplicate、testと出力SHA-256を記録し、採否を決定する。
