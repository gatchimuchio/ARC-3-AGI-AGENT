## 1. 運転全体

**現状再観測 → 初回公式E5 → 基準線確定 → 失敗原因抽出 → 横断規則学習・改良 → 再提出 → 次の改良**。

この流れは一つの委任目的。工程やタスクが完了するたびに必要な結果を保存し、その結果を次工程の入力にする。**報告や1タスク終了を理由に、次工程を停止させない。**

## 4. 工程C：公式基準線からの性能開発

| タスクID | 対象 | 実施内容 | 判定 |
| --- | --- | --- | --- |
| C0：全体診断 | 初回公式ログ・既存公開ゲーム・HDS状態 | 成功・HOLD・故障・資源消費を同じ台帳へ照合 | 具体的な改良課題を列挙 |
| C1：観測品質 | 対象・構造・関係・変化 | 誤観測、未観測、時点混同を局所修正 | 対象の認識再現性向上 |
| C2：行動因果 | 行動前後の状態遷移 | 目的到達に寄与する操作条件を抽出 | 無根拠作用・無駄作用を減少 |
| C3：HOLDの解決 | 失敗署名と追加観測条件 | HOLD発生原因の学習・情報取得・適応を改善 | 合法な自律判断の拡大 |
| C4：記憶→推論→適応 | Learning Machineの学習状態 | 個別課題から横断規則を抽出、転移試験 | 別状況での再現 |
| C5：実行効率 | 作用回数・時間・メモリ・Kaggle制限 | 実行方針と提出パッケージを調整 | 到達成果当たりの消費改善 |
| C6：横断回帰 | 複数ゲーム・未知状況 | C1～C5の採否と悪化項目を測定 | 保持条件PASS・改善採択 |

C0で効果が大きいと判明した課題を優先し、**C1→C5の固定順を目的化しない**。故障がない工程は飛ばす。C6は各改良の局所回帰も兼ねる。

### C工程の1単位

1. 現在のAGENTS.md、制御/現在状態.json、最新実装と失敗ログを読み直す。
2. 優先度の高い**1つの故障・1つの保持条件**を選定。
3. その1課題だけの新規指示書を発行し、既存の指示書と区別して保存。
4. 変更前証拠を固定し、局所修正を実施。
5. 対応する試験・横断回帰を実行。
6. previous／current／delta、失敗署名、採用・棄却の理由を記録。
7. 次の優先課題を選定して指示書を発行し、**継続実行**。

人間への報告はCの各単位で行ってよいが、正常なタスク切替時に人間の返事を必須としない。

## 5. 工程R：改良版公式再提出

| タスクID | 作業 | 成立条件 |
| --- | --- | --- |
| R0：再提出候補選定 | Cで検証された候補を基準線と比較 | 公式評価を行う目的があり、提出枠・期限・規約に適合 |
| R1：Notebook梱包 | 最新の検証済み改良を最小パッケージへ反映 | SDK、HDS根拠、オフライン、9時間以内 |

| R3：公式評価 | Competition Rerun | 公式受理・公式スコア取得 |
| R4：比較・記録 | 初回および直前版と比較 | previous／current／delta・回帰・失敗署名 |

R4後、C0へ戻り次の改善を行う。単に「提出した」ことを終点にしない。提出回数や期限に制限があれば計画内で優先配分し、不要な連打を避ける。

## 7. 自動遷移の判定表

| 発生条件 | 次の操作 | 人間待ち |
| --- | --- | --- |
| E0～E4が有効 | E5へ | 不要 |
| E5受理 | 初回基準線保存→C0 | 不要 |
| E5一時障害 | 診断→修復→再試行 | 不要 |
| 個別改良がPASS | 履歴保存→次課題→必要ならR | 不要 |
| 個別改良がFAIL | 失敗署名保存→復帰／再設計→次課題 | 不要 |
| HDS HOLD | 根拠・必要観測を記録→適法な学習運転 | 不要 |
| 競技の提出枠や期限に抵触 | 計画の最適化・再配分。規約外実行はしない | 原則不要 |
| 明示的禁止・新たな認証・権限外変更 | 作業停止し必要な権限だけ照会 | 必要 |
| 所有者による停止命令 | 直ちに停止・状態を保存 | 必要 |

「E5前の個別承認」「E5後に別指示待ち」「課題終了ごとに指示待ち」は、本工程には存在しない。

## 8. 品質保証と記録

必須の台帳フィールド：

- 指示書ID、現行コードSHA、提出Notebook版・公式評価時刻。
- 今回の観測とその範囲、旧観測の出典と時点。
- 成功／失敗／HOLD、作用数・ステップ・環境状態差分。
- 前回結果、現在結果、delta、保持条件の合否。
- 採否と根拠、次課題、運転継続状態。

**記録は追記・版保存。既存記録を最新結果で黙って書き換えない。**

## 9. 真の中断条件

停止は以下に限る。

1. 所有者からの明示停止。
2. 実行にない権限を取得しなければならない（Kaggle・GitHubログインや保護された操作）。
3. 競技規則・AGENTS.md・秘密情報保護との具体的矛盾があり、許可内で回避不能。
4. 重大な破壊、情報漏洩、回復不能な変更の危険があり、合理的な代案もない。
5. 利用可能な実行資源が終了した（状態保存後、再開点を指定）。

品質検査の不合格は原則**是正工程の開始条件**であり、直ちに人間への差戻しを意味しない。

## 10. 受入水準

- 初回公式提出：E5受理の実測記録を取得。
- 学習開発：少なくとも1件の横断規則候補について、変更前後・転移試験・失敗署名を記録。
- 再提出：公式の受理結果を初回基準線と比較して保存。
- 運転：工程境界での人工的な承認待ちなし、1タスク1指示書、AGENTS再読、履歴保全を両立。

**工程表はCodexの運転を止める装置ではなく、次の仕事を確定させる装置とする。**
