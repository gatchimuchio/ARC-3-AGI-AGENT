# C4-001 同一ゲーム内レベル間転移の評価

## 目的

C4「記憶→推論→適応」の局所課題として、探索方針の統計を次レベルへ持ち越すことが公開環境の進行に寄与するかを確認する。現行 `MyAgent` はゲームごとに探索方針を新規作成し、同じゲーム内ではレベル遷移後もその方針を保持する。ゲーム間共有とは分けて評価する。

## 比較

- carry: 現行方針。レベル完了後も行動回数、報酬、盤面、色の統計を保持する。
- level reset: レベル完了後に探索方針の統計を初期化する。乱数生成器の状態は引き継ぎ、初期盤面・Action選択乱数の差を持ち込まない。
- どちらも公開観測・合法Actionだけを使い、1ゲーム最大80 Action、GAME_OVER後はSDK RESETで再試行する。

## 手順と採否条件

1. 既存のsplit seed `20261022` の開発5環境をseed 7/31/73で比較する。行動報酬や探索係数は調整しない。
2. carryがcompleted levelsを維持し、少なくとも完了までのAction数またはno-opを再現性をもって改善した場合だけ、未使用holdout 20環境をseed 31で一度評価する。
3. holdoutでcompleted levelsを維持し、完了Action数とno-opが悪化せず、開発側で見た改善方向が再現した場合に限りruntime候補へ採用する。それ以外は変更しない。
4. Kaggle公式score、hidden環境への効果はこのローカル実験から推定しない。

## 実装範囲

アブレーション専用の `検証/ARC3探索Actionローカル評価.py --ablate-level-transfer` を使う。runtime agent、HDS v0.4.2、提出bundle、保護ファイルは変更しない。評価器はレベル完了の正の差分時に統計をリセットし、乱数状態のみ保持する。
