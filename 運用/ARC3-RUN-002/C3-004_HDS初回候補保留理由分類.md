# C3-004 指示書：HDS初回候補の保留理由分類

- 指示ID: `ARC3-RUN-002-C3-004`
- 版: 1.0／2026-10-23（JST）
- 根拠: C4-004で提出agentのHDSは空状態から開始しAction応答後に更新されないこと、C1-002でAction番号＋結果要約のshadow学習はAction別多数派を超えなかったことを確認した。現在のagentはHDS HOLDを記録し、独立した探索Actionを継続する。4つの汎用構造語彙のどこで候補・適用性・確信が失われるかは公開環境で集計されていない。

## 目的

実際の固定dev 5環境の初回進行中公開観測を、空HDSと現行共通観測経路へ与え、語彙別の適用性、作用適用性、目標/作用候補数、保留理由・不確実性の有無を匿名aggregateする。原因が「対象構造に非適用」「現HDSに支持規則なし」「語彙照会未確認」「複数解釈」等のどこにあるかを分類し、次の修正対象を選ぶ。

これは診断であり、性能改善やHDS candidateの認可根拠を求めない。

## 固定条件・保持範囲

- 固定dev split seed `20261022`の先頭5公開環境、environment seed `31`。各環境につき初回の`NOT_FINISHED`公開観測1件だけを使用する。
- 新規HDSを環境ごとに1つ作り、現行`公開観測から候補を照会する()`を一度だけ呼ぶ。Action要求、HDS学習、reset/retryは行わない。
- 出力は語彙別status/countの合計のみ。game/level ID、GUID、盤面、色値、座標、Action引数、軌跡、観測指紋、理由文字列を保存しない。
- Action候補は実行せず、探索policyにも返さない。全候補の`実行許可:false`を保持する。
- `AGENTS.md`、現在状態、HDS core、提出agent/runtime、candidate/Notebook/kernelは変更しない。Kaggle API/Notebookを操作しない。

## 受入と成果

1. 固定環境・開始観測が5件得られたことを確認し、各語彙の集計対象数を記録する。
2. HDSが照会前後で学習更新されないこと、action requestが0件であることを確認する。
3. summaryに識別子、raw観測、条件値、候補内容、理由文字列が混入しないことをtestする。
4. 対象suite、Ruff、CLI、`git diff --check`を実行し、source/input/output SHA-256を保存する。
5. HOLD原因の分類と証拠に基づき次の単一課題を選ぶ。候補を増やす・HOLDを解除する・runtime接続する判断はこの診断では行わない。
