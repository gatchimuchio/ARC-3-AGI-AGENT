# C1-002 指示書：HDSへの公開Action応答shadow学習評価

- 指示ID: `ARC3-RUN-002-C1-002`
- 版: 1.0／2026-10-23（JST）
- 対象: ARC3提出agentとHDS v0.4.2の経験記録経路
- 根拠: C0は既存候補照会がread-onlyと確認。現行agentは開始後の一観測だけをHDSへ照会し、作用前後の公開観測を`HDS学習系統.処理する()`へ渡さない。探索Action側のフィードバックは別policy統計に保持される。

## 目的と仮説

Action応答の公開情報から、game/level識別子・盤面・座標・ファイル名・hashを含まない最小のAction条件と結果要約を作り、HDSへ順次記録するshadow評価を行う。HDSが記憶・推論状態を更新し、後続応答の一部を正しく予測できるなら、将来の別課題でHDSの状態更新を候補側へ接続する検討材料になる。

これは性能改良やHDSがActionを認可できる証拠を求める工程ではない。結果は探索policyとSDK Action選択へ一切返さない。

## 許可する範囲

- `検証/ARC3HDS公開遷移shadow評価.py` の新規追加。
- C2-003の保存済み公開dev seed31応答記録を読み、1環境ごとに空のHDSを起動して時系列処理する。
- HDS入力は条件としてのAction番号、結果としての可視変化有無・level進行有無・新規可視盤面の真偽値だけとする。RESETは除外する。
- 各環境の先頭75%を`処理する()`へ与え、後半25%は`照会する()`のみで予測を採点する。
- 予測coverage、正答・誤答・競合数、学習状態版数、原理状態、実行時間を集計し、新しい診断報告とローカル出力を追加する。

## 禁止と保持条件

- HDSの候補・予測をAction選択、HDS確定、SDK実行認可に使わない。既存候補Notebookへ接続しない。
- 入力にgame/level ID、観測指紋、run GUID、色番号、座標、盤面、trajectory、seed、filename、hash、公式hidden情報を含めない。
- gameごとに独立した空HDSを用い、別ゲームへ状態を共有・転送しない。この結果を横断学習と呼ばない。
- HDS v0.4.2の中核、`接続/ARC3提出agent.py`、`AGENTS.md`、`制御/現在状態.json`、正本ポインタ、v2.0文書、v1.0履歴を変更しない。
- Kaggle Notebook/kernelは更新せず、Competition Rerunもしない。

## 検証と受入

1. 各gameの入力で必須5特徴以外がHDSへ渡らないことをtestする。
2. RESETを除く学習呼び出し数が75%分割の訓練件数と一致し、後半は照会だけで経験台帳が増えないことを確認する。
3. 訓練後にHDS状態版または経験台帳が更新され、予測出力が後半実測と比較可能であることを確認する。
4. 正答率は訓練データ全体の多数派基準とAction別多数派基準へ同じ後半サンプルで比較する。採用可能な学習接続候補とみなすには、HDSが複数Action状況を予測し、coverage上でAction別多数派より高い正答を示し、誤答・競合がなく、条件値と結果値が公開特徴から追跡可能であること。達成しなければ「現行入力要約では有用な学習未確認」と記録する。
5. いずれの結果でも、shadow評価から競技性能、公式score、cross-game transferを主張しない。

## 終了条件

入力field、HDS更新件数、後半照会の台帳非更新、予測coverage/精度/反例、状態版数、時間、出力hash、targeted testsを記録する。Action経路への接続判断はこのtaskで行わず、結果に応じて次の独立指示書へ進む。
