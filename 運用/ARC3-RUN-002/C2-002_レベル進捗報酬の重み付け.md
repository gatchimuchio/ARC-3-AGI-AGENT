# C2-002 指示書：レベル進捗報酬の重み付け

- 指示ID: `ARC3-RUN-002-C2-002`
- 版: 1.0／2026-10-23（JST）
- 対象: 観測駆動探索Action方針の応答報酬と合法Action選択
- 前回基準: C3-002候補 `ARC3-SUBMIT-009`／公開local holdout seed 7/31/73

## 観測と仮説

C3-002後の同一20公開holdout、3 seedを横断集計すると、Action1/2/3/4/5/7は計3,579回でレベル増分0、盤面変更なしは129回。一方、座標引数を持つAction6は1,194回中5回のレベル増分を生み、変更なしは331回（27.7%）だった。現行報酬はレベル増分に加えて新盤面+0.5、可視変化+0.25、no-op -0.5を加算し、公開変化量をレベル進捗の代理に使う。

仮説: UCBが可視盤面変化・新規性を積極的に報酬化すると、目標進捗へ結び付かないが派手に変化するActionを過大評価する。レベル増分を主信号にし、可視変化は探索の同点補助へ下げれば、同一game内で進捗を生んだ作用を再利用でき、完了前の無駄Actionを減らす。

## 目的

公開レベル進捗を探索効用の主信号とする重みを、開発splitだけで決定し、holdout seedへ固定適用してC3-002版と比較する。Action IDや座標色への事前固定優先度は追加しない。

## 許可する範囲

- `接続/観測駆動探索Action.py` の作用前後報酬係数、およびその係数を比較可能にする最小評価接続。
- `検証/test_観測駆動探索Action.py` の進捗・新規盤面・no-op報酬の回帰試験。
- 公開dev 5環境（既存split seed `20261022`）で係数候補を比較し、一候補を固定してから公開holdout 20環境のseed 7/31/73で採否を判定。
- 完了level数に加え、完了までのAction数、level増分、no-op、GAME_OVER/RESET、WIN、illegal、duplicateを別々に記録。

## 禁止と保持条件

- holdout結果を係数調整へ使用しない。C3-002 holdout結果は事前仮説の根拠であり、変更後は固定検証として扱う。
- game/level ID、filename、hash、既知解、trajectory、hidden state、評価器内部、非公開正解でruntime分岐しない。
- 行動番号だけを根拠にACTION6等を優遇しない。現行 `available_actions` と観測駆動の選択を保つ。
- HDS HOLDを確定Actionへ変換しない。HDS v0.4.2、`AGENTS.md`、`制御/現在状態.json`、v2.0正本・履歴は変更しない。
- GAME_OVER RESET境界、WIN終端、80要求上限、座標枯渇安全停止、観測ごとの高々一回stepを保持する。

## 検証

1. 現行係数のdev seed 7/31/73をpreviousとして固定する。
2. 進捗報酬を強め、可視変化・新規性を同点補助へ弱める一つの事前登録候補をdev 5環境で同条件比較する。
3. devで係数を選んだ後、holdoutのseed 7/31/73へ固定適用し、C3-002出力と照合する。
4. targeted tests、Ruff、公式offline runner、repo environment audit、bundle依存閉包を通す。
5. baseline比較でAction効率または到達を改善し、3 holdout seedで最大levels completedを下回らず、WIN・illegal・duplicateの回帰がない場合のみ採用する。改善しなければ棄却し、失敗署名を保存して次課題へ移る。

## 終了条件

- 変更の前後報酬差と、HDS確定系統からの独立を試験で確認する。
- 同じ公開条件でprevious/current/delta、到達・Action数・no-op・終端・合法性を記録する。
- 採用時のみ `ARC3-SUBMIT-010` とKaggle通常実行へ進む。Competition Rerunはquota/期限を再確認し、未充足時はローカル成果を保存して他の改善へ継続する。
