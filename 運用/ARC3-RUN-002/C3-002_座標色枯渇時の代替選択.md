# C3-002 指示書：座標色枯渇時の代替選択

- 指示ID: `ARC3-RUN-002-C3-002`
- 版: 1.0／2026-10-23（JST）
- 対象: 観測駆動探索ActionのACTION6座標選択
- 前回基準: C3-001 GAME_OVER後SDK RESET再試行

## 根拠

- seed 73の同一公開holdoutで、`ft09-0d8bbf25` がC2停止版・C3再試行版ともに30要求で `exploration_hold` になった。
- C3報告では当該runが30要求で `exploration_hold` になった。コード経路上、ACTION6の選色後に選択色の未試行座標がない場合に `None` を返す。
- 既存実装は盤面内で未試行座標を持つ色に候補を絞る前にUCB最上位色を選ぶため、選択色の座標だけが枯渇し、他色に未試行座標が残るケースでも方針全体を止める可能性がある。C3記録には停止時の可視盤面・座標候補内訳を保存していないため、実故障の直接再現ではなく、コード検査から得た修正仮説を対象とする。

## 目的

ACTION6で最上位色に未試行座標がないとき、現在の可視盤面に未試行座標を持つ色だけを候補として選び直す。全色の座標が試行済みなら、既存の安全なHOLDを維持する。

## 許可する範囲

- `接続/観測駆動探索Action.py` の可視色・座標候補絞り込み。
- `検証/test_観測駆動探索Action.py` に、UCB最上位色の座標枯渇時に別の適格色を選ぶ回帰試験を追加。
- 公開local dev/holdoutで、既存seed・同一開始集合・同一Action予算のC3前後比較。

## 禁止と保持条件

- `available_actions` にACTION6がない場合は座標Actionを送らない。
- 現在の公開盤面にない色、試行済み座標、範囲外座標を選ばない。
- すべての色に未試行座標がない場合に、重複座標を強制したりActionを捏造したりせずHOLDする。
- game/level ID、filename、hash、保存trajectory、正解情報をruntime分岐や座標選択に使わない。
- HDS v0.4.2、`AGENTS.md`、`制御/現在状態.json`、v2.0正本・旧履歴を変更しない。

## 検証

1. テストで、UCB最上位の色が盤面上すべて試行済みでも、未試行座標を持つ別色を選び、その座標が合法かつ未試行であることを確認する。
2. 全色の座標が試行済みなら `None` を返す安全条件を確認する。
3. ACTION6なし・通常色探索・RESET/WIN境界の既存testを再実行する。
4. devとseed 7/31/73の同一公開holdoutで、最大levels completed、policy hold、legal/duplicate、Action要求数をC3-001前後で比較する。
5. 対象故障でpolicy holdを解消し、illegal/duplicateを増やさず、既存seedの最大levels completedを維持または改善した場合のみ候補を再構築する。

## 終了条件

- 座標枯渇色に引きずられず、別の適格色へフォールバックする。
- 座標選択の再現性、可視情報境界、合法性、全色枯渇時のHOLDを保つ。
- 指定holdout seedでC3-001の最大到達を下回らず、停止原因・Action要求数・比較hashを記録する。
- 条件を満たさない場合は候補Notebookを更新せず、原因を記録する。
