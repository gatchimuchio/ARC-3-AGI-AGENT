# C2-025 汎用モデル推論候補のオフライン起動確認

## 目的

現在の観測駆動candidate v4（公式public `0.25`）とHDSを保持し、別候補として、公開された汎用モデル推論NotebookをKaggleの同じGPU・オフライン入力で起動できるか確認する。公開実装のスコア記述を本候補の性能証拠へ転用しない。

## 採用理由

C1/C2/C3/C4/C5/C6の既存診断・ablationでは、現在の手書き探索方針へ加えるID-free一般規則のうち、事前受入条件を通るものが出ていない。公開モデル解は、画像・中間Frame・操作履歴を汎用LLMへ渡し、ツールを通して探索する別アーキテクチャで、現在の行動選択機構と独立に比較できる。

参照元はDaniel Franzenの公開[Notebook](https://www.kaggle.com/code/dfranzen/arc-agi-3-milestone-2-solution)と[ソースリポジトリ](https://github.com/da-fr/arc-agi-3-solution)。著者の[write-up](https://github.com/da-fr/arc-agi-3-solution/blob/main/WRITEUP.md)はpublic score `27.89`を報告するが、これは著者の外部結果であり、現在のsubmissionや本candidateの結果ではない。Notebook自身は公開demoを4 passで走らせる意図を記す一方、著者はその全demo実行を完了できなかったと記述している。

## 使用条件と境界

- 公開Notebook取得物SHA-256: `88A379F17C3A4BA8C98715FC23155346CCD6EB289BDAFEBADFC61A3178F9D9BD`。
- GitHub `HEAD`確認値: `10882e332d883af3e61616df8c8a17d03a328a75`。コードライセンスは上流のApache-2.0。全文をcandidate directory内へ保持した。
- Qwen baseおよび派生model metadataは`qwen-community-1.0`。モデルの条件は同梱model sourceとQwen公式licenseで確認する。重みはKaggle入力から使い、Notebookへ複製しない。
- Kernel metadataはGPU `NvidiaRtxPro6000`、`enable_internet=false`、Competition・source dataset 2件・model source 2件、およびupstreamと同じPython 3.12 Docker image digestを指定する。
- 固定ID/filename/hashの答え分岐、hidden/evaluator情報、推論時trainingを使用しない。初回(v2)の開発実行は公開offline環境の一覧順で1件のみ、1 pass、1ゲーム600秒上限。v3再確認ではcold-load待ちとの重なりを考慮して同じ1環境・1 passのまま上限を1,200秒にする。IDを指定した選択は行わない。
- Competition rerun pathは提出Quotaを使うため本タスクでは実行しない。公式quotaは現時点で残り0件。

## 実施手順

1. upstreamのnotebook outputsを除去し、現在候補と区別できるprivate kernelへ保存する。
2. offline実行設定だけを1環境へ制限し、live competition pathのagentロジックは変更しない。
3. Notebook形式・metadata・ライセンス・offline/no-ID guardを静的検査する。
4. Kaggle通常実行を1件で開始し、kernel状態とログからモデル起動、Action経路、正常teardownを確認する。
5. 完了後もv4を基準候補として保持し、同一public環境比較が済むまで能力改善を主張しない。

## 受入条件

- private kernelとして登録され、Internetが無効、GPUがRTX PRO 6000、指定competition/model/dataset inputsがある。
- 取得元の実行outputがcandidateに残っていない。
- offline smokeが完成し、model server/ARC runtime/agentを起動して少なくとも一つの合法Actionと観測を通す。Notebook結果・Parquet placeholderを公式scoreと誤認しない。
- offline上限により最大1環境・1 passに留まる。v2の初回上限は600秒/ゲーム、v3はcold-load重なりを反映した1,200秒/ゲーム。live competition pathの環境全件選択を維持する。
- 既存の公式submission historyとquotaが変わっていない。

## 初回実行の失敗と修復

version 1はKaggleの既定Python 3.13で起動し、Pennyroyalのoffline wheelhouseが要求する`aiohttp==3.14.3`のCPython 3.13 wheelを持たず、推論サーバー起動前に停止した。Notebookのローカル構文やmodel input不足ではない。上流kernel metadataに含まれていた固定Docker image (`gcr.io/kaggle-private-byod/python@sha256:57e612b484cf3df5026ee4dcc3cb176974b22b2bc0937fb1e16132a8be4cb13c`)をversion 2 metadataへ戻し、Python 3.12の実行環境を再現して再試行する。

受入後は、25の公開環境を使う1-pass比較の実行時間見積り、v4との同条件指標、採否の事前条件を次の1指示書で定める。

## v2 実行結果

- Kaggle private kernel v2は`KernelWorkerStatus.COMPLETE`。ベンチマークは2026-10-23 13:01:01–13:11:02 UTC、1公開環境(`sk48-d8078629`)、1 pass、13 Action、10,735 generated tokens。サマリー上は`gave_up`、score `0.00`、8 level中0完了で、候補の能力改善は確認していない。
- `serve.log`はRTX PRO 6000 Blackwellで38 shardのweights読込後、2026-10-23 13:09:33 UTCにserver startupを記録した。ベンチゲーム時計は13:01:01 UTCに始まっており、server readyまで8分32秒が重なった。残り時間で13回のモデル推論/Actionが記録され、HTTP 200応答と盤面変化を確認した。従ってv2はKaggle/Python 3.12/GPU/model/server/ARC runtime/Action/observation経路の起動証拠にはなるが、600秒全体の探索結果ではない。
- すべての実Actionは各時点の`UP/DOWN/LEFT/RIGHT/MOUSE/UNDO`のうち`UP/RIGHT/LEFT`で、イベントは`NOT_FINISHED`の観測と盤面差分を記録した。1回目の`RESET`は盤面変化なし。score 0を勝利または公式評価と扱わない。
- private-kernel出力は`出力/ARC3-RUN-002-local/C2-025-kaggle-output/v2/`に保存。競技submission historyはv4 (`57541830`, public `0.25`)とbaseline (`57527856`, public `0.00`)が最新のままで、新規競技提出は発生していない。
- 結論: Python 3.13 wheel不整合はDocker image pinで修復し、通常Kaggle kernelは完走。offline smokeの経路受入は通過、モデルのゲーム解決能力は未確認。

## v3 起動待ち補正

- v2では`SERVER_STARTUP_TIMEOUT=12分`を過ぎるとserver未readyでもbenchmarkを開始する。冷起動の実測ではgame timerの開始8分32秒後までserverがreadyにならず、600秒wall-clock capの大半が起動待ちと重なった。
- Notebookの開発専用`max_runtime_s_per_game`だけを600秒から1,200秒へ変更し、環境数1・pass数1・server startup wait・モデル・Action policy・competition pathは維持した。競技モードはこの上限を適用しない。

## v3 再確認結果

- Private kernel version 3は`KernelWorkerStatus.COMPLETE`。ベンチマークは2026-10-23 13:33:08–13:53:08 UTC、1公開環境(`sk48-d8078629`)、1 pass、84 Action event（初期RESETを含み、gameplay Action 83件）、104,760 generated tokens。結果は`gave_up`、score `0.00`、8 level中0完了。
- `serve.log`のserver readyは13:41:11 UTCで、game timer開始から8分03秒後。従って1,200秒枠のうち約11分58秒がready後の推論時間だった。event logには83件のgameplay Actionすべての後に`NOT_FINISHED`観測があり、76件で盤面が変化、7件はfull-board同一。server logにはモデルAPIのHTTP 200応答がある。非法Actionやlevel進行は見つからず、モデル・server・ARC runtime・Action/observation経路は検証できた。
- 同じ公開開始状態のローカルv4評価(`same_public_start=true`)は80 Action（gameplay 79）、完了level 0。評価器と時間条件が異なるため性能差を主張できる比較ではないが、少なくともこのゲームではv3にも進行優位を確認していない。
- 監査用保存出力: `出力/ARC3-RUN-002-local/C2-025-kaggle-output/v3/`。`benchmark.json` SHA256 `bb58ebbd6ff1f2731a9923a2b19f3395e92f2a1563f5f60a3b8ff29c72e3ef9f`、event log SHA256 `25b6dea967dc60d4ddf1521bb63c6910d194b181be82d053c11d48815f340cfc`、`serve.log` SHA256 `3813704dd60e41162359eecb026a4ab223ac46efa28b37bde5b7673ba52aabff`。出力は`.gitignore`対象。

- 結論: **C2-025の環境起動受入はPASS、モデル能力改善は未確認のため候補は未採用**。v1のPython 3.13不整合は固定Docker image、v2の短い実推論枠は1,200秒dev capで対処したが、score 0.00を成果へ昇格しない。次の限定評価へ進む。
