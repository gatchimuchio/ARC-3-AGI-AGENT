## 実行2：RESET/HOLD-onlyから、合法な多手ゲーム攻略へ

1. \`is_done()\`はSDKの実終了・完了・合法な資源上限で終了。\`NOT_FINISHED\`を通常の即終了としない。
2. \`choose_action()\`は画面・履歴・候補推論から合法行動を選ぶ。操作した**次フレームと進捗/失敗**を必ず観測し更新する。
3. \`HDS/学習系統/v0.4.2\`と\`記憶/事前記憶/v0.4\`から、公開観測に対応する一般的作用・機構候補を得る。
4. HDSが採用HOLDなら、その内部状態は保持しつつ、**独立した安全・合法な探索判断**から観測価値のある行動を出す。禁止の候補自己承認は実装しない。
5. 行動上限を公式・ローカル予算に合わせ、ゲームごとに進行/攻略を繰り返せるようにする。無限ループ/無根拠ランダム連打を得点改善と誤認しない。
6. 旧\`検証/test_ARC3提出agent.py\`が「停止できた」を成功とする部分を、**多手数・合法性・継続・結果更新・正当な終了**の新しい試験に改める。

成果：1ゲームのエピソードが合法行動を複数実行し、少なくとも**観測→行動→状態変化/失敗→次の行動**を記録。レベル突破がなければ原因を修正し継続。

## 実行3：公開ゲーム全体で採点・学習能力の実証

- 公式SDKで公開のゲーム群を、同じ初期状態、行動/時間予算、seed（適用時）で自動実行する。公式Starterの\`make play-local\`の動作を参照し、既存リポに統合する。**1手オフライン確認では代用禁止**。
- **クリアゲーム数、到達レベル/全レベル、成功操作数、失敗/無進展の操作数、操作効率**を集計し、各ゲーム実行軌跡を保存。
- 公開観測に基づく機構・記憶を更新する前A/後Bを同条件の未見ゲーム/未見状態で比較。ID/固定操作列の丸暗記による偽得点を排除。
- 得点ゼロなら最大失点原因（観測不足、作用推論不足、探索不足、候補採否、予算、終了判定）を分類し実行2へ戻る。

成果：当該版・資産で再実行可能な公開ゲームの結果と未見適応結果。

## 実行4：Kaggle版の構築 → 公式Competition Rerun

既存リポの構築例（現行の\`--help\`、Notebook metadata、公式手順と必ず突合。別の空の新フォルダを使う）。

\`\`\`bash
python -m uv run --locked python 道具/ARC3提出物構築.py --owner tecchannn --output-dir 出力/ARC3-SUBMIT-V6
python -m uv run --locked kaggle kernels push --path 出力/ARC3-SUBMIT-V6
\`\`\`

1. \`道具/ARC3提出物構築.py\`の同梱一覧を点検し、**一般化可能な記憶を合法な形でNotebookに入れ実際に読み込む**。学習動作・ゲーム行動・終了判定が本番で一致するか確認。
2. \`kaggle kernels status <owner>/<actual_slug>\`と\`kaggle kernels output ...\`（実際のmetadataのslug）等で通常Runが成功したか追跡。**RUN COMPLETEは中間の技術確認に過ぎない**。
3. 公式の[ARC3 Starter手順](https://docs.arcprize.org/arc-prize-2026)通り、該当Notebookの**Submit to Competitionで\`submission.parquet\`を選び、Competition Rerunを発火**させる。現行の認証済みUI/公式APIで操作する。CLIに存在しないRerunコマンドを捏造しない。
4. 競技提出後は**当該Notebook版・公式提出ID・Leaderboardの確定スコア**を確認。Kaggleの通常Notebook実行と競技再実行の2段階を台帳で区別。
5. 日次提出枠や実権限がなければ同じ版を連打しない。PENDING中も公開ゲームの得点向上を進める。

成果：実際にゲームをプレイするコードが公式採点された数値と、その版・公開再現試験の結び付け。

## 実行5：スコア上位を狙う反復

低スコアゲームを**失敗機構別**にまとめ、対象IDを条件分岐に使用せず、機構改善で攻略・行動効率を上げる。局所試験→公開ゲーム全体→同条件比較→学習前後→正式Rerunを繰り返す。レベル数を増やすだけでなく、**攻略できたレベルの行動削減**にも取り組む。局所スコア改善が公式で再現できなければ環境差・梱包差・記憶の差を追う。
