# ARC-AGI-3 Codex実行指示書 v6.0 — このリポ専用

対象：\`gatchimuchio/ARC-3-AGI-AGENT\`。共通3ファイルと本トラックの仕様書・工程表を適用。**ARC2を編集しない。**

## 絶対目標

**ARC3の初見ゲームを観測・推論・学習・行動で本当に攻略し、同条件で再現し、KaggleのCompetition Rerunで公式スコアを獲得・改善し、首位と100%を狙う。**

SDK接続、RESET、HDSのHOLD監査、Notebook RUN COMPLETEは**手段**であってゴールではない。データが存在するだけでも学習実証にはならない。

## 実施指示（順序固定）

1. 現行HEAD・\`AGENTS.md\`・旧正本・\`制御/現在状態.json\`・\`HDS/学習系統/v0.4.2\`・\`記憶/事前記憶/v0.4\`・公式SDK・提出履歴を確認。旧版は削除せず新Owner指示v6の採用経緯を残す。
2. 専用工程表「実行1」で1手SDK試験と**本当のゲーム進行**を区別し、最初の基準線を採録。\`57527856\`の競技得点と、別版\`23.86\`の由来を混同しない。
3. \`MAX_ACTIONS=1\`、\`is_done()\`即終了、RESET専用\`choose_action()\`、\`実行許可:false\`伝播を**実ゲームの失点原因**として修復。HDS自身の判断を勝手にPASSにせず、独立した合法探索実行を設ける。
4. 公開ゲームを複数手実行し、**画面→候補→行動→画面変化→規則更新→次手**のログを得る。進行しなければエンジン/探索を改修、停止を合格としない。
5. 専用工程表「実行3」で公開ゲーム群を実測し、学習適応の前後、クリア、レベル、行動数、時間、再現を比較。ゲームID別固定リプレイで見かけの成果を作らない。
6. 専用工程表「実行4」に従って本番Notebookを作成し、**通常Run後のCompetition Rerunを本当に完了**させ、対応する確定得点を得る。
7. 最大の失点原因を直し、同条件公開評価で改善した版だけKaggle公式で試す。締切まで繰り返す。

## これを達成扱いしてはならない

- 「SDKに接続できた」「1回RESETした」「HOLDとして安全停止した」。
- 「Notebook COMPLETE」「\`submission.parquet\`が生成された」「その中の得点らしい値が1」。
- 「過去に23.86と出たから現行にも23.86ある」。
- 「成功軌跡を9件分そのまま反復した」「ゲームIDに応じた既知操作を再生した」。
- 「記憶が読み込まれたから学習した」。**推論と行動と未見での変化**が必要。

## 完了条件ではなく反復検収

| 観測項目 | 必要な実証 |
|---|---|
| 最小実動 | SDK合法行動を**複数手**出し、実状態変化を観測・反映 |
| ゲーム能力 | 公開ゲーム/レベルで実際の進行・クリア・操作数を計測 |
| 記憶使用 | 本番実行系のHDS・汎用記憶参照と行動への因果経路 |
| 学習・転移 | 観測前後の機構状態と未見ゲーム攻略差 |
| 再現 | 同じ初期条件・SDK・予算・版で複数回評価 |
| 公式 | Notebook版、競技Rerun提出ID、**確定公式得点** |
| 改善 | 最大の失点機構の修正による同条件のスコア上昇 |

公表済み低スコアでも今回の実力として正直に記録し、改善の材料にする。**公式スコア向上の循環が競技目的**である。認証・ルール等の真の権限阻害だけ、試したコマンドと必要な操作を報告して停止。
