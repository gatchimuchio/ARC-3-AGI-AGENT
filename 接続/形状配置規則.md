# 公開教師から形状配置を構造適用する

固定 HDS v0.4.2 に公開の原問題・完成例・前後作用例を通常入力し、同じ一個の学習状態を目標対応・選択・局所移動・接触投射で共有する、追加専用の単体接続である。内部の対象、役割、関係、候補、規則照会、学習記録、保存判定、探索状態の正本は日本語 schema。外部原票の作用だけは契約の `id/data/x/y` を保持する。

## 適用範囲と結果の意味

- 公開成功資料二つの全七問題、計14組の問題と完成画像を fixture に保持する。別成功資料も開発資料であり盲検ではない。
- 目標対応は原問題の全対象と全目標の直積を捨てずに照会する。三辺可視で一辺が遮蔽された矩形候補は条件付きであり、実答えによる事後確認と区別する。
- 状態生成モデルの支持範囲は、二つの3×3青対象、二つの可視閉輪郭目標、搬送候補なしの構造。ゲーム名、level、出典番号では分岐しない。ここを越える構造は保留する。
- 検証対象の最初の原問題では全8132状態、全48792辺（支持48564、保留228）、全4完成終点を列挙する。各状態で四方向と二対象内の各9座標を全保持し、残り4078座標は保留する。座標代表は同値類の表示用で、他の座標を落とさない。
- 四終点の最短作用数は11・12・20・21。全体最短11作用の8経路は座標同値類単位である。全四終点の全最短親DAGも保持する。4終点すべてが11作用という意味ではない。
- 原問題から全グラフを保存した後に完成画像の占有位置と照合する。原答えから経路を引かず、ID lookupも行わない。これは条件付きのオフライン証拠であり、新規環境成功や全七問題の完了ではない。外部環境への作用は一切発行せず、実行許可は常に偽。

## 固定知覚と学習の分離

`形状配置知覚.py` は色、連結成分、閉領域、選択白点、画面端UI、形状多重集合から全正確被覆を作る固定知覚である。初期形状の在庫だけを履歴として使い、予測内の真の個体番号を画像から観測できたとみなさない。全分解を返し、単体探索は一意な場合だけ採用する。複数分解の場合に作用前提と結果が一致するかの一般的な集合値推論は本APIの支持範囲外であり、保守的に保留する。

`形状配置規則.py` はHDS入出力と前提語彙を接続する。自由判定は作用前の移動先画素が床/輪郭であることだけから作る。後状態から自由ラベルを作らない。搬送候補は作用方向相対の位置・色の全配置。接触投射は前状態で被接触形状を一単位ずつ前方にずらした全地形役割列（64画素/3画素単位から21段）と選択/被接触形状から作る。距離減少による候補剪定、後期level分岐、教師再生、未支持物理の補完はない。

HDSが学習するのは、これらの型付き前提から形状対応・選択・一単位移動・投射変位への規則である。物理モデルそのものをHDSが発明したとは主張しない。

`形状配置探索.py` は問題だけを受け取り全幅探索する。状態描画は青対象跡を床/既知輪郭に戻し、青充填と代表マーカーを描く固定仮定。矢印アニメーションや画面端UIは再現しない。`形状配置検証.py` が同一公開原票の最初の19作用を先に照合し、対象・位置・選択の全一致、背景不一致0、初期遮蔽18画素の全露出を検査する。この検査は未知環境に対する因果保証ではない。

## 教師・入力順・失敗資料

`検証/資料/形状配置公開教師.json` は空からの正本363教師を固定順で保持する。

1. 局所145件。直積関係語彙、関係種類交互順。
2. 目標20件。
3. 選択175件。
4. 投射23件。原票時系列順。

出典は由来の索引だけであり、HDS条件には含めない。全23投射は同じ363状態に入り、旧系と投射系をruntimeで切り替えない。教師・原票は公開提供資料だけを使い、非公開解やevaluatorは使わない。

初期24投射のうち1観測（別成功開発資料130→131行）は、選択18画素/被接触36画素と、その逆の二分解が成立し、作用前提と予測占有が異なった。原観測と全分解を観測保留として保存し、363正本には入れない。旧24学習は比較専用であり、由来に曖昧ラベルが入った状態を正本として残さない。

`形状配置比較教師.json` は独立二特徴/直積関係 × 時系列/関係種類交互の2×2、および旧24投射の二入力順を、同じ全観測集合で再現する。空から比較し、元の隔離・反証状態は上書きしない。16実反例、白選択点と画面端UIの混同、接触図形の色連結による24辺/最短親4辺不整合も失敗資料として保持する。比較は成功した表現だけに観測を選び直す実験ではない。

## 単体構造API

リポジトリと `HDS/学習系統/v0.4.2` を Python import path に置く。

```python
from hds学習系統 import HDS学習系統
from 接続.形状配置規則 import 公開教師を教える, 目標対応全候補を読む
from 接続.形状配置探索 import 形状配置を構成する, 全体最短経路を読む
学習系 = HDS学習系統()
記録 = list(公開教師を教える(学習系, 公開教師資料['教師']))
全対応 = 目標対応全候補を読む(問題盤面, 学習系)
構成 = 形状配置を構成する(問題盤面, 学習系)
全最短 = 全体最短経路を読む(構成)
```

単体APIは構造的支持範囲を確認するが、呼び手は状態描画を利用する前に公開前後モデル照合を行うこと。共通観測入口・制御状態・権限文書は変更しない。

## 再現手順

標準ライブラリのみ。新規出力先を指定し、既存出力は上書きしない。

```sh
PYTHONDONTWRITEBYTECODE=1 python 道具/形状配置教師検証.py --出力 検証結果/形状配置/再現例 --比較
PYTHONDONTWRITEBYTECODE=1 python -m unittest 検証.test_形状配置規則 -v
PYTHONDONTWRITEBYTECODE=1 python -m unittest discover -s 検証 -v
```

CLIは逐次学習ログ・実学習状態・全構成・全分解・全最短経路・全HOLD・モデル照合・原答え事後照合・資源計測・現在状態を保存する。空状態および同じ統合状態への合成反例対照は、どちらも1状態・支持0・保留6・完成0となる。反例は投射前提への実測15,0を0,0に反転した対照で、実観測教師に混ぜない。全領域の採否が全体保留になることを確認する。

保存例外は例外種別と理由を保存判定に残し、保存保留を成功扱いしない。途中失敗も生成済みログ・状態を残す。最大常駐メモリはLinux `ru_maxrss` のキビバイト、時間は実測壁時計秒。

## 照会記憶と意味状態監査

同じ一個のHDS・同じ型付き前提への照会だけを読み取りキャッシュし、すべての辺へ展開する。候補や教師を削らない。全37種類の照会、全8132状態の全辺・全最短親を回帰する。照会は永続化状態の照会/学習判定カウンタを増やすので、byte不変とは言わない。その二独立カウンタだけを除いた記憶意味状態は一致する。

公開実装では `台帳.py` の識別番号は種類別、`実行系.py` の照会は推論と全体隔離ゲートを読み出すだけ、`適応.py` の予測条件は境界・原理状態・型付き観測であり、照会番号に依存しない。永続化はカウンタも保存する。初回移植CLIはこの符号化辞書を通常辞書として比較して誤検出したため保留保存となった。修正は接続検査の除外位置を識別子状態内だけに限定したもの。元失敗出力を保存している。

### 検証済みの再現例

本候補の確定再現は、新規28試験を含む全112試験で99成功・13既存試験保留（外部原票path指定待ち）。新規試験にskipはない。全14場面の104対象目標対と94全割当、960局所観測照合も保存する。確定CLIは74.506秒・最大304264キビバイト（約297.1MiB）。実行条件で時間とメモリ値は変わる。

局所の2×2比較では、独立二特徴は両入力順で保留、直積関係は時系列で保留・関係種類交互順で支持。旧24投射は時系列で支持・関係種類交互順で保留。ただし時系列の旧24状態にも曖昧教師由来があるため、正本への採用はしない。比較状態・ログはすべて残す。

### 独立監査後の境界修正

空盤面では対象0・目標0の空割当を支持としない。対象と目標がともに非空の場合にだけ全割当を列挙する。反証学習状態と各比較学習状態の保存保留も、本体保存と同様に記録後ただちに例外保留へ移り、照合成立や保存失敗=falseへ到達させない。

空盤面・反証保存故障・比較保存故障の3試験を追加し、新規系統31試験は全成功（104.034秒）。故障注入は既検証363状態とグラフを再利用し、失敗state未作成、保存保留記録、全体現在状態の保留、途中ログ保持を確認する。既存84試験も別途実行し71成功・13skip。合計115試験、102成功・13既存skipとなった。元28試験の全8132状態・全48792辺・94全割当を含む正常系も再実行済み。旧候補・旧試験結果は監査修正前の証拠として保持する。
