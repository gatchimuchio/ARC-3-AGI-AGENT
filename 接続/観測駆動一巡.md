# 記録観測での一巡と Runtime Memory 原記憶

`記録観測の一巡を処理する` は同じHDSへ直前と次の公開観測を渡し、共通候補照会、記録された作用との照合、全応答相/目標進行/予測残差の照合、原記憶保存、次観測の候補照会を行う。

駆動源は公開教師の観測記録。環境step、確定作用発行、Action送信はない。候補と記録作用が一致してもエージェントが実行したことにはしない。HDSへ新しい教師経験は投入せず、保存を実学習や規則採用と呼ばない。公開照会によるHDSの問合せ管理情報は更新され得る。

## 作用照合と差分

作用番号/引数の完全一致と、同じ本体mask内の別座標という可視関係を別記録にする。後者は対象単位の既存作用モデルに基づく条件付き対応で、座標依存反例や因果差を排除しない。不一致を無効Actionと断定しない。

既存候補の全対象予測差分から、全画素予測が矛盾なく復元できる場合のみ全応答相と比較する。前色不一致、mask不明、異なる複数予測は未確認として全候補を保持し、一つを選ばない。予測しない画素の保存は固定モデル仮説として明記し、HUDも含む残差を保持する。可視no-opでもhidden変化なしとは判断しない。公開評価を原票として保持するが、完了数・成功・WINをrewardへ読み替えない。明示された有限数値のrewardとその公開出所がある場合だけ報酬欄へ写し、それ以外は未観測を維持する。

## 原記憶

`記憶/README.md` とOwnerのRuntime Memory範囲に沿い、前後全frame、公開識別子/通番/可用作用、作用発生主体、目標/対象/関係、作用前提、可視差分、hidden/reward不明、成立/失敗条件、因果/反証候補、HOLD、適用範囲、出所を保持する。

一巡ごとの新しい識別子のディレクトリに、照会前の `原票.json`、照会後の `結果.json` を分けて保存する。一時ファイルをfsyncした後にrenameし親ディレクトリをfsyncする。捕捉可能な途中例外は原票と失敗結果を保存して再送出する。プロセス強制終了などを捕捉できない場合も先行原票は残り、結果ファイルなしの一巡は未完了として扱う。保存失敗は未保存/未確認の全記録と保存参照を持つ例外で返し、未完了一時証拠を削除しない。ストレージが一切利用不能な場合まで永続保存を保証しない。

この追加は原記憶の蓄積まで。蓄積した記録をHDS教師へ変換する採否、改訂/統合/分割/無効化などの運用は未実装。生成候補の繰返し照会を実環境運転やfresh成功へ読み替えない。

## 再現

```
python 道具/観測駆動一巡検証.py \
 --状態 学習状態.json --原票 recording.jsonl --原票SHA256 SHA256 \
 --前行 11 --応答行 12 \
 --図式教師 検証/資料/複合図式公開教師.json --記憶先 /tmp/観測原記憶
```

行指定はハーネスのみ。隣接二行であること、原票digestを確認し、game ID等の外部metadataを作用引数と分離する。旧score/win_score形式はハーネスでのみ公式levels形式へ変換する。Runtimeにはゲーム/レベル選択条件を渡さない。CLIは実照会後のHDS状態も保存する。

実資料で確認: 列図式11→12はACTION5完全一致、118相中17相が旧目標に一致し、次問題の候補1件。複合184→185は座標不一致と同じ本体役割の条件付き対応を両方保存し、全相残差[0,2012]、完成相1件、次問題候補1件。追加学習/環境送信はともにFalse。空/人工反証状態は前後候補0。公開no-opは可視差分0とhidden未観測を保存する。

回帰: `python -m unittest discover -s 検証 -p 'test_*.py' -v`。
