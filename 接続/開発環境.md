# ARC3 開発環境

Python 3.12で、現行HDSの実装・試験、公式ARC3環境の観測、Kaggle配布物の検査を行う。
戦略と学習機械の正本は `制御/現在状態.json` に従う。環境構築では選択・変更しない。

## 復元

WindowsではPython 3.12とGitを導入し、リポジトリのルートで実行する。
今回のPythonは3.12.10、uvは0.12.19。依存全体を `uv.lock` に固定した。

```powershell
$env:PYTHONUTF8 = '1'
python -m pip install --user uv==0.12.19
python -m uv sync --locked
```

HDSは `HDS/学習系統/v0.4.2` からeditableで導入する。仮想環境のActivateは不要。
エディターのPythonには `.venv/Scripts/python.exe` を指定する。
既存コードの日本語ファイル読書きのため、実行時は `PYTHONUTF8=1` を設定する。
OneDriveの同期負荷が大きい場合は、チェックアウト全体を同期対象外の場所へ移して復元する。

| 依存 | 用途・固定条件 |
| --- | --- |
| arc-agi 0.9.8 / arcengine 0.9.3 | 今回実取得したコンペ同梱wheelと同じ版 |
| NumPy 2.4.4 | 今回のコンペ同梱版と同じ配列計算 |
| pandas / pyarrow | 提出形式Parquetの読書き |
| Matplotlib | SDKの描画、診断画像 |
| JupyterLab / ipykernel | 観測用Notebook |
| pytest / Ruff | ローカル試験、構文・重大な静的エラー検査 |
| Kaggle 2.2.4 / kagglesdk 0.1.37 | 認証、配布取得、Notebook操作 |

モデル・GPUの依存は、推論方式と実行先が未選択のため追加していない。

## コンペ配布物

大会への参加・規約同意は本人が行う。認証が未設定なら、公式CLIでログインする。
認証情報は利用者ホームの `.kaggle/` に置き、リポジトリやNotebookへ記載しない。

```powershell
python -m uv run --locked kaggle auth login
python -m uv run --locked kaggle competitions download arc-prize-2026-arc-agi-3 -p 入力/Kaggle
python -m uv run --locked python -m zipfile -e 入力/Kaggle/arc-prize-2026-arc-agi-3.zip 入力/Kaggle
```

2026-10-22の取得では148ファイル、展開後48,969,679 bytes、公開環境25個。
`接続/Kaggle配布マニフェスト.json` に各ファイルのサイズとSHA256を保存した。
取得した本体・wheel・ZIPはGit管理対象外。SDKの公開API経由で環境を使う。
配布内容が更新された場合は診断の不一致を調べ、マニフェストを自動更新しない。
同梱wheelにはLinux専用バイナリがあるため、Windowsでは `uv.lock` から復元する。

## 構築確認と日常操作

配布物を取得した後、次のスクリプトでlockからの復元、仮想環境内のカーネル登録、監査を行える。
Python 3.12本体は事前に導入する。

```powershell
& ./道具/開発環境構築.ps1

# 依存・Parquet・描画・配布物の完全性
python -m uv run --locked python 道具/開発環境確認.py

# 公開環境をネット接続せずに初期化し、1作用後の実観測を既存ARC3境界へ渡す
python -m uv run --locked python 道具/開発環境確認.py --offline-game

# 本人の認証による大会ファイル一覧と提出履歴の読み取り
python -m uv run --locked python 道具/開発環境確認.py --kaggle

python -m uv lock --check
python -m uv pip check --python .venv/Scripts/python.exe
python -m uv run --locked ruff check .
python -m uv run --locked python -m compileall -q HDS 接続 道具 検証

# 日常の環境確認
python -m uv run --locked pytest -q 検証/test_開発環境確認.py 検証/test_資源計測.py 検証/test_証拠保存.py

# 全体回帰。既存の997件再教示など長時間の処理を含む
python -m uv run --locked pytest -q

# カーネル ARC3 (Python 3.12) を選択
python -m uv run --locked jupyter lab
```

デフォルトの診断はネット通信しない。オフライン実行は配布済み `environment_files` を使い、
ARC APIキーは不要。診断の1作用はSDK・観測経路の接続確認であり、攻略・能力改善の証拠ではない。
`OPERATION_MODE=competition` が設定された環境ではローカル診断を実行しない。

既存の実状態試験 `検証/test_輪郭実状態.py` は `WA_TEST_HDS` 未設定ならskipする。
承認済みの実状態がない場合、旧資産から勝手に選ばない。
連動教師の再教示CLIにある350MiBの `RLIMIT_AS` 制限はLinux専用であり、
Windowsでは明示的に実行を拒否する。通常のimport・試験・保存・資源計測はWindowsで使える。
Windowsでの証拠保存確定はwrite-through移動を使う。電源断からの復旧は今回の検証範囲に含めない。

Ruff 0.17.1は、CPython 3.12で合法な `;match=` を構文エラーと誤判定する。
同じ現象を0.14.2でも確認したため、該当する既存の `接続/配色内部/応答.py` だけを
Ruff対象から除外し、上記 `compileall` と既存の配色試験で検査する。処理内容は変更していない。

## Kaggle実行との境界

公式StarterはPython 3.12、ARC SDK、pandas、pyarrowを使用する。
コンペはKaggle Notebookで実行し、提出ファイルは `submission.parquet`。
CPU/GPUとも実行9時間以下、インターネット無効が公式条件。
採点時はゲートウェイとCompetition Modeを使い、ローカル環境と実行制約が異なる。

現在のリポジトリには、採用済みの大会提出agent・Notebookは定義されていない。
公式Starterの `agent.py` / Notebook生成経路を参照し、HDSによる作用の採否を保った上で別途接続する。
通常Notebookの保存・実行、コンペへの提出、隠し環境での採点はそれぞれ別の段階である。
この環境構築ではNotebook送信・新規提出・採点を実行しない。

通常検査はローカルで行う。既存Actionsの起動は `workflow_dispatch` のみにしている。
当該手動workflowにはmain以外のブランチを削除する既存jobがあるため、通常検査には使わない。
