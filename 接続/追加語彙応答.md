# 鎖・形状の記録応答への薄い照合接続

## 目的

同じ HDS と公開前観測から作られた作用候補に対し、実記録作用と全応答相を照合する。環境stepを呼ばず、実行許可は常に false。目標が解けたこと、全画素の作用因果、不可視効果の不在はこの接続から断定しない。

## 既存モデルの再利用

- 鎖: 既存 StateModel.predict の根/腕/珠の次状態。単根・右軸・矩形・一意色珠の固定知覚範囲。既存 render は線/レールの画素を正規化するため、全画素残差は別に保存し、一致の証明とはしない。
- 形状: 既存「公開前後でモデルを検証する」の選択・局所移動・接触投射部分だけを「可視前状態から作用を予測する」へ抽出。元の batch 検証も同じ純粋関数を呼ぶ。二つの3×3青対象・二つの可視目標という既採用作用範囲を継承する。

入力は同じ HDS、直前観測、現在観測、予測作用、語彙名、記録実作用。語彙名は共通入口が公開構造から選んだ既存語彙であり、game/level ID 分岐ではない。直接検証で与えた記録作用の予測照会と、共通候補から採用可能な作用かの検査は区別する。

## 全相と採否

全応答 frame と相間の実差分を既存相記録で保持する。各相に可視意味状態、前意味一致、予測意味一致、旧構造一致、解析失敗を記録する。前状態にも予測状態にも対応しない相、構造不明相、予測未支持は保留する。末尾相の予測意味一致を必要とするが、先頭相を作用結果/完成画面へ固定しない。

形状では前後対象の占有外かつ最下段を除く画素変化も照合し、あれば保留。対象が覆っていた背景とマーカー全画素の復元は未証明であるため、「全画素応答成立」は常に false。鎖も固定描画と実画素の残差を全て残す。可視意味no-opは hidden no-op を意味しない。

予測作用と実記録作用の番号・引数が厳密一致しない場合、未可用作用、順序不正、別実行は保留。RESET・完了数変化・終端では旧履歴を破棄し、次状態へ旧作用履歴を渡さない。完了増分はそのまま証拠として保持するが、この接続には鎖/形状の完成目標照合をまだ実装していない。

## 一巡への接続

採用済み列/複合応答は従来の経路を維持する。鎖/形状のみ新しい意味応答照合へ進む。観測駆動一巡は記録作用に厳密一致する旧候補がある場合だけ予測作用を渡す。一致候補がなければ原記録・候補不一致を保存し保留する。新しい Runtime Memory への記録は HDS の追加学習ではない。

## 検証と限界

軽量回帰は未知中間相、前状態へ戻る末尾、実作用不一致、RESET/実行/進捗/終了境界、可用性/通番、no-op、予測例外と既存一巡の保存失敗を検査する。実2286状態では、既存形状19前後の旧新全出力比較と、公開原票の全行/全相照合を別に行う。原票フレームの重複保存を避ける場合も SHA256・行・相参照を残す。失敗・未対応・HOLDを件数から除外しない。

この段階は限定モデルの応答照合であり、全レベルの作用モデル・新規環境走破・鎖/形状の完成相同定は未成立。採否は全原票結果と旧2語彙の同状態回帰を確認してから行う。


## r2 の成立記録と不足の履歴

検証基底は dfa63d（161ファイル）、統合時の基底は後続の3f3a3f（183ファイル）。後続追加は今回の既存変更箇所と重ならない。注入した保存済み共有 HDS は2286経験、SHA256 `7cbd7e5c652731cc2181c6103ac9cb1a8666320a939c4f5e8da94e35152db371`。正常評価中に教師を追加せず、同状態への人工反証は採用外の検査として分離した。

公開鎖1記録と形状3記録を全数照合し、2330作用・4457応答相のうち167作用が限定された意味照合成立、2163作用が保留だった。これは環境成功数でも自律実行数でもない。鎖51作用、形状116作用が成立し、対象知覚/既存作用モデル範囲外、途中表示、RESET/進捗境界などの失敗は全て残した。既存形状19前後の batch 検証は抽出前後で全出力一致したが、新入口の可視前提では結合・輪郭遮蔽・進捗を保留するため、最初の19作用中16作用の限定意味照合成立に留まる。

r1は予測HOLDの理由を文字列で保存し、当該HDS照会の原応答全体を新gate結果へ返していなかった。r2は薄い受信点が同じ公開照会を一回だけ転送し、入力6欄、応答の状態/内容/追跡情報、例外を「当該HDS照会記録」に保持する。別の前候補照会を代用しない。全原票で1414照会、うち保留時992照会を保存した。追加欄だけを除く全JSONはr1と完全一致し、動的metaにも差はなかった。空HDSの原応答が「出力」でも予測群が空なら接続は保留する。原応答を「断定保留」へ書き換えない。

### 無加工の共通一巡

- 旧列・複合: 同じ2286状態・同じ記録前後観測で応答、成立/保留条件、作用照合、予測/実差分を維持。
- 鎖初期: 共通入口の11支持経路を保持。記録作用4へ10件の経路支持が一致するが、応答の中間相0が未確認で保留。10種類の異なる作用という意味ではない。
- 形状初期: 共通入口の8支持経路を保持。同じ記録作用4へ8件が一致し、全相の意味応答照合成立・保留0。8種類の異なる作用という意味ではない。
- 空状態と人工反証: 新しい鎖・形状応答は保留、次履歴なし。全HDS照会記録を保持。正常保存状態を上書きしない。

どの一巡も作用発生主体は公開記録であり、環境stepは呼ばず実行許可はfalse。形状の成立も全画素/不可視効果/レベル完成の保証ではない。

### 保存失敗と救済

通常形式による途中版一巡の原記憶が約146MiBとなり、保存予算を超えた。その成果を削除せず、検証ハーネスだけの保存受信点を可逆gzipへ置き換えた。Memory全値・候補・推論・採否は加工せず、通常JSONの決定的byte列とSHA256、gzip復号byte一致を記録した。これは通常I/Oそのものの実証ではない。通常の原票先行保存、途中例外、最終保存失敗の回帰は別に維持する。

不足版の追加鎖実例（公開行62→63、7×7・4珠）では、原票先行保存後にprocessがexit137 / Killedとなり一巡は未完了。正確な内部停止箇所と原因は未測定で、OOMとは断定していない。この1実例を成功件数へ入れず、初期例の成功/保留で置き換えない。

r2は形状一巡の最終保存で書込前容量上限に達してexit1となった。原票は保存されたが、in-memory結果は未保存だった。予算承認後、同じ2286状態・同じコード・同じ原票で形状一巡と空/反証のみを再生成し、結果314,932,119 bytesをgzip4,605,652 bytesで全量保存した。全原票評価を再実行したとは扱わない。救済は71.9秒、peak RSS 2,622,772 KiB。資源停止・上限失敗・救済結果をそれぞれ別の証拠として保持した。
