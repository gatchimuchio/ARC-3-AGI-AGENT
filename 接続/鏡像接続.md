# 鏡像関係の自己完結接続候補

基準は main 647ac82c064a4e5b3a229aff026a0f2f2de86dfd の79ファイルsnapshot。本候補は専用接続・教師・検証・文書を追加するだけで、共通入口、HDS v0.4.2、制御・権限を変更しない。

## 単体API

`接続.鏡像接続.鏡像候補を作る(frame, available_actions, hds, *, 既観測形状=None, 観測履歴=None, 経路も作る=True)`

- 外から渡した同じHDSで、目標、方向、本体包含選択、軸循環、D4、選択保持を照会する。内部に別の学習機や学習済みルール表を持たない。
- `frame` は外部SDKの64×64画素、`available_actions` はその時点の全作用番号。`id/data/x/y/frame/score/state/full_reset/action_input` は外部契約の記号。
- 内部意味項目は日本語。無変換の公開原票と旧実験証拠は証拠専用であり、runtime解法選択には使わない。資料索引・ID・ファイル名・hashによる問題分岐はない。
- 最初の観測で得る形状を`既観測形状`として保存し、継続時に渡す。省略時は今回を初期観測として8近傍成分から形状を取る。接触後に形状を再初期化してはならない。
- 全作用を残し、クリック4096座標を画素セル内の全同値座標群として損失なく保持する。未学習作用や包含外もHOLDとして残す。目標は有限全配置、被覆同値類の全直積を保持する。
- 全完成候補へ軸→本体移動の具体手順を構成し、各段を全再識別・選択履歴gateで再照合する。x先行の表示代表は最短経路でも全軌跡探索でもない。別順序/undo等を不可能と断定しない。
- 複数現在仮説は全保持する。全現在仮説・全事後仮説が同じ占有差分と選択対応を与えなければHOLD。対象IDを過去計画から引き継がない。

`鏡像作用を照合(前観測, 既観測形状, 作用, hds, *, 観測履歴=None)`は意味観測の単段入口。空盤面・空形状の空割当は支持しない。

`鏡像全応答を照合(前照合, 応答, hds, *, 既観測形状, 前得点=None, 前状態=None)`はSDK応答の全相を保持する。途中相の知覚不明、占有/選択不一致、得点/状態/RESET境界はHOLD。末尾だけの一致で途中相を捨てない。全相が整合したときだけ`次観測履歴`を返す。予測直後の`次観測照合用予測`を実行済み履歴として無検証で採用しない。取消等の未学習作用は履歴を確定しない。

全APIで`実行許可=False`。自動実行器やSDK送信器を追加していない。

## 学習と固定計算の由来

実学習は公開教師をHDS標準APIへ直列入力した1051件。目標・単軸反射関係、157局所作用、72可視性付きD4、包含選択、軸循環、203選択保持の順序を保存している。203件は195保持/8変更。前後どちらかの選択が曖昧な12候補は支持へ混ぜない。

固定処理は3×3セル知覚、色役割、8近傍の初期形状、D4/鏡映計算、全和集合一致分解、有限配置列挙、同値類圧縮。これらをHDSが発明したとは主張しない。

旧848状態と旧14手順98段の観測HOLD、42成立/4未採用・18HOLDの中間版、独立表現/提示順の隔離失敗、各実入力、反証状態を旧証拠archiveに保存する。新支持ができても旧履歴を消さない。

## 再現

候補repository根から実行する。

```sh
PYTHONDONTWRITEBYTECODE=1 python -m unittest discover -s 検証 -p 'test_*.py'
PYTHONDONTWRITEBYTECODE=1 python -m 接続.鏡像教師CLI --全検証 --人工反証 --全問題再構成 --出力 /tmp/鏡像検証.json
```

既定は同梱の保存HDSを読む。毎回1051件を再学習しない。全再学習を明示すると空HDSから同一順序で実投入し、全実入力出力とactual状態を保存する。

```sh
PYTHONDONTWRITEBYTECODE=1 python -m 接続.鏡像教師CLI --全再学習 --全検証 --人工反証 --全問題再構成 --状態出力 /tmp/再学習HDS.json --出力 /tmp/再学習検証.json
```

`教材を教える(教材,hds=外部HDS)`は同じ外部HDSへ追記できる。既学習状態に再投入すると経験が重複するので、追加対象・入力順・既投入区間は呼出側が管理する。全再学習CLIは保存状態読込と排他。

保存処理は実ファイル存在、再読込、書出後hashを確認する。無書出/例外/破損を完了扱いしない。出力は指定先の親が存在する必要があり、失敗は非0終了になる。人工反証は元HDSの複製にのみ入力する。

## 証拠と限界

- 46合成手順1524段の履歴gateは条件付き閉包。fresh実環境成功ではない。
- 原票3245遷移の占有2694一致と選択保持3102一致は重複する指標であり加算しない。
- 複数応答17作用54相を全保持する。公開監査の15作用48相もその部分集合として含む。開発資料の行75は途中3相が知覚不明、末尾一致でもHOLDを解消しない。
- 二軸合成22手順968段は固定演算の条件付き。空像D4同値12手順82段は複数候補のまま。画面外空像を唯一関係に昇格しない。
- 16問題の公開答えは開発確認済みで未見最終評価ではない。非公開解・evaluator内部は使わない。
- 全候補と全応答の保持は成功率向上を意味しない。共通戦略への採用や自動遷移は本候補では行わない。

## 応答確定直前の再照会

前照合の支持を期限なしの許可として持ち越さない。全応答APIは、前観測・実行作用・観測履歴から現在の外部HDSへ元作用/選択保持を再照会し、現在の目標照会もHOLDでないことを要求する。途中で同じHDSへ反証が入った場合、または空HDSが渡された場合、以前の予測と画素が一致しても履歴継続を確定しない。

`前状態`は履歴確定の必須境界情報。応答に`score`がある形式は`前得点`、`levels_completed`がある形式は`前完了レベル数`との比較を要求する。両方ある場合は両方を確認し、どちらもない場合はHOLD。省略や変化を不変とみなさない。応答の`action_input.id/data`は前照合の実作用と一致を要求する。`data.game_id`は由来だけで作用意味の比較に使わない。GUIDの同一性と直前観測・作用・応答の順序対応は呼出側の必須責任であり、単体APIの画素一致はその代用にならない。
